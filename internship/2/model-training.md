# Agent 数据与大模型训练：从监督微调到多轮强化学习

你之前训练过视觉模型，已经接触过数据、损失、反向传播和对照实验。本篇把这些经验迁移到语言模型和 Agent：**一次训练样本是什么，哪些 token 计算损失，反馈怎样变成训练信号，参数怎样更新，训练后怎样验证。**先读 §1—4，再读 §5—7；§8 是训练排错。这里只给学习资料和示例，并不表示你已经训练过 NLP 模型。

## 1. 从一条任务到三种改进方式

假设希望模型完成“根据笔记回答实验预算”。它调用查询工具后得到 `100`，但最终答成了 `1000`。可以有三种不同的改进：

1. **改系统而不训练模型**：把工具结果放进上下文，增加格式校验或调整提示。模型参数不变。
2. **监督微调 SFT**：准备问题、工具调用、工具结果与正确回答的示范，让模型学习在这些上下文下生成目标 token。模型参数或适配器参数改变。
3. **强化学习 RL**：让模型针对问题采样多个行为轨迹，通过验证器得到奖励，再依据反馈调整生成策略。模型参数改变；验证器可以是规则、环境或模型。

还可用偏好优化：同一问题对比更好与更差的回答或轨迹，让模型更偏向前者。训练方案与 Harness 优化可以组合，但要分别设置对照，否则无法知道收益来自哪里。

## 2. 语言模型训练中实际发生了什么

### 2.1 Token、概率、交叉熵与梯度

**Tokenizer**把文本转换为 token ID，模型对前文预测下一个 token 的概率。设输入 x 和目标回答 token 序列 y=(y₁,…,yₜ)，自回归模型的联合概率按链式法则拆成：

\[
p_\theta(y\mid x)=\prod_{t=1}^{T}p_\theta(y_t\mid x,y_{<t}),\qquad
L_{\rm SFT}=-\frac{1}{T}\sum_{t=1}^{T}\log p_\theta(y_t\mid x,y_{<t}).
\]

θ 是待训练的权重；`y_<t` 是第 t 个 token 前的目标 token。训练中常用 **teacher forcing**：预测当前位置时，前文是数据中的正确前缀；生成时前缀来自模型自身，早期错误可能影响后续输出。若一个目标 token 的概率是 0.1，损失为 `-ln(0.1)≈2.30`；提升到 0.8 后损失约 0.22。损失下降意味着数据中的目标 token 概率通常上升，不能单凭训练 loss 断定真实任务成功率提高。

**一次训练步**：数据经 tokenizer 和 collator 形成批次 → 前向得到 logits → 与目标计算交叉熵 → `loss.backward()` 求梯度 → 优化器 `step()` 更新参数 → 清梯度。优化器、学习率、训练精度、梯度裁剪、scheduler 和随机种子都影响结果；训练数据更新与评测环境需记录版本。

### 2.2 数据长什么样，为什么需要 loss mask

一条工具调用样本可按逻辑组织为：

```text
工具说明: read_note(name: string)，返回指定笔记
用户: 实验 A 的预算是多少？
助手工具调用: read_note({"name":"A"})
工具返回: 实验 A 使用 100 次模拟
助手: 实验 A 的预算为 100 次模拟。
```

模型有时要学习生成工具名与参数，有时学习根据工具返回回答。真实数据要按具体模型的 **chat template** 序列化角色和工具信息，保留调用 ID 或关联关系；不同模型格式并不通用。教师数据中的工具结果应与实际工具一致，不能把模型猜测伪装成执行结果。

**loss mask**指定哪些位置参与损失：常见做法只训练助手输出，对用户提示、工具说明、工具返回和 padding 屏蔽。也有其他训练目标，必须查具体配置。对于两段助手输出，要保证工具调用和最终答案对应的目标 token 都按计划纳入；别把模型本应预测的 token 错误屏蔽。

PyTorch 通常用标签 `-100` 表示该位置不参与 `cross_entropy`；注意需要把 logits 与**下一个位置的标签**对齐。假设输入 token 是 `[用户A, 用户B, 助手C, 助手D]`，labels 是 `[-100, -100, C, D]`：

| 模型看到的位置 | 要预测的下一个 token | 是否计入 |
|---|---|---|
| 用户A | 用户B | 否，目标为 -100 |
| 用户B | 助手C | 是 |
| 助手C | 助手D | 是 |

填充时还需 attention mask 区分有效 token；**attention mask 控制注意力中是否可见，loss mask 控制是否计分**，两者不是同一概念。最终分隔符/EOS 是否计分也要明确；拼接样本时要防止跨样本泄露。

下面是 **PyTorch 示意**，只展示 shift 和 mask；本环境没有 PyTorch，未运行此段，实际代码应根据模型输出和批次形状检查：

```python
import torch
import torch.nn.functional as F

def causal_lm_loss(logits, labels):
    # logits: [B, L, V]；labels: [B, L]，忽略位置 = -100
    shift_logits = logits[:, :-1, :].contiguous()
    shift_labels = labels[:, 1:].contiguous()
    # 全部目标被忽略时先报错，避免得到无意义的 NaN
    if not (shift_labels != -100).any():
        raise ValueError("batch 没有参与训练的目标 token")
    return F.cross_entropy(shift_logits.view(-1, logits.size(-1)),
                           shift_labels.view(-1), ignore_index=-100)
```

### 2.3 预训练、SFT、后训练各自是什么

**预训练**常在大规模数据上学习下一个 token，得到通用语言和知识能力；**SFT**使用任务示范强化指令遵循、格式或工具调用；**后训练**是宽泛阶段名称，可包含 SFT、偏好优化、RL 等，具体顺序取决于团队。上下文放入新资料是推理，不会自动更新权重。领域继续预训练和 SFT 的分界在真实工程里也可能按数据目标或流程命名，讲清数据与损失比死记名字更重要。

## 3. Agent 数据：轨迹怎样形成可用样本

**轨迹 trajectory**是一条任务中多轮消息、工具调用、观察、结果与元数据；**rollout**是按某个策略在环境中运行得到轨迹的过程。例子：`问题 → 查询(A) → 100 → 回答100 → 验证成功`。一条长轨迹可整理成 SFT 示范、偏好对或 RL 样本，但每种用法的标签与筛选不同。

1. 定义任务分布、环境版本、工具接口、完成标准；为每个独立运行设置可重置环境与任务 ID。
2. 从真实授权记录、人工示范、模型生成或模拟环境采集轨迹；标记来源、模型/提示版本、是否人工修订和时间。
3. 校验工具调用格式、参数、关联 ID、工具观察与最终环境状态；去掉敏感信息、去重，避免把伪造的成功当标签。
4. 检查质量：成功不代表过程每步正确；失败也可能用于偏好或错误分析。不能靠一次 judge 自动判定全部真值。
5. 按任务族、文档/仓库/关卡来源划分训练、开发和测试，避免高度相似轨迹跨集合。记录模型预训练时可能见过公开基准的限制。

**合成数据**可通过模型提出任务、环境执行、verifier 过滤生成；生成容易，难点是多样性、正确标签、无泄漏及不过拟合验证器。**数据飞轮**指采集→标注/验证→训练或系统更新→评测→再采集，但它不必然带来收益：若错误标签反复进入数据，可能放大偏差。

### 3.1 冷启动与离线/在线

SFT 冷启动是先用一批相对可靠的示范让策略具备基本格式或解题能力，再根据需要做 RL；如果基础策略总是无法获得非零奖励，直接 RL 可能难学到东西。**离线**数据在当前更新时预先收集；**在线**过程会随当前策略继续采样环境，具体 RL 实现可能使用采样策略快照并多次更新。旧轨迹的生成策略与当前策略不同会带来分布偏移，不能把它们一律当成当前策略刚采的。

## 4. 全参数微调、LoRA 和 QLoRA

### 4.1 为什么需要参数高效微调

全参数微调更新选定模型的全部权重；对大模型而言，梯度和优化器状态等需要额外显存。**LoRA**把部分权重更新限制为低秩矩阵乘积，冻结原始权重，只训练较小的增量。设线性层原矩阵 `W₀ ∈ R^(d_out × d_in)`：

\[
W=W_0+\Delta W,\quad \Delta W=\frac{\alpha}{r}BA,\quad
A\in\mathbb R^{r\times d_{in}},\quad B\in\mathbb R^{d_{out}\times r}.
\]

r 是秩，α/r 是常见缩放；具体实现可不同。原矩阵有 `d_out*d_in` 参数，LoRA 增加 `r*(d_in+d_out)` 个可训练参数。例：4096×4096、r=8，原矩阵约 1678 万参数，A+B 为 65536。它减少的是**所选层的可训练参数**，不等于整个训练显存按此比例减少：仍需存储基础权重、激活及其他训练状态。适配器可按条件合并到权重以简化推理；多个任务切换与量化合并有各自限制。

**QLoRA**的一类做法把冻结基座权重以低位量化存储，再通过计算路径训练 LoRA 适配器。基础权重被冻结，但并不是“整个训练都只用 4 bit”；计算、激活和适配器精度由实现决定。量化有误差，训练与部署要核验模型、精度、库与硬件兼容。

### 4.2 手写一个 LoRA 线性层

以下是帮助理解的 PyTorch 模板；本环境未安装 PyTorch，**本次只检查语法，未执行或验证训练效果**。它将已有 `nn.Linear` 作为冻结基座，A 随机初始化、B 初始化为零，因此初始增量为零。实际模型注入、权重合并、checkpoint、dropout 和量化需要专门库或更多工程实现。

```python
import math
import torch
from torch import nn
import torch.nn.functional as F

class LoRALinear(nn.Module):
    def __init__(self, base: nn.Linear, rank: int, alpha: float):
        super().__init__()
        if rank <= 0:
            raise ValueError("rank 必须大于 0")
        self.base = base
        for parameter in self.base.parameters():
            parameter.requires_grad_(False)
        self.A = nn.Parameter(base.weight.new_empty(rank, base.in_features))
        self.B = nn.Parameter(base.weight.new_zeros(base.out_features, rank))
        nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))
        self.scale = alpha / rank

    def forward(self, x):
        # F.linear(x, A): 最后维度从 d_in 变 r；再经 B 变 d_out
        return self.base(x) + self.scale * F.linear(F.linear(x, self.A), self.B)
```

初始时 B=0，因此第一步反向传播时 A 的梯度可能为零、B 可以得到非零梯度；B 更新后 A 才开始接收梯度，这符合这种初始化的计算图，不一定是代码出错。若不冻结 base 参数就不是此处的标准冻结基座 LoRA。输入、A、B 的 dtype/device 必须兼容。

## 5. 强化学习基础：从一个动作得到梯度

### 5.1 策略、奖励、回报与优势

策略 `πθ(a|s)` 表示给定状态 s 选择动作 a 的概率。在 LLM 中可以把下一 token 看成动作；更粗的粒度也可把一次工具请求看作动作，但实际损失通常对生成 token 计算。**奖励 r**是环境或评分器给的反馈，**回报 G**是后续奖励的折扣和：

\[
G_t=\sum_{k=t}^{T}\gamma^{k-t}r_k.
\]

例如先得到 -0.1 的调用成本，再得成功奖励 1，γ=0.9，则初始回报为 `-0.1+0.9×1=0.8`。**价值 V(s)**估计该状态未来期望回报，**Q(s,a)**还指定首个动作，**优势 A(s,a)=Q(s,a)-V(s)** 衡量动作相对该状态基准的好坏。这是理想定义；实践常用采样与近似估计。

**策略梯度**的直觉：正优势动作提高概率，负优势动作降低概率。一个常见估计是：
\[
\nabla_\theta J(\theta)\approx \mathbb E[\nabla_\theta\log\pi_\theta(a_t|s_t)\,\hat A_t].
\]

log 概率的梯度指出如何提高被采样动作的概率；优势控制方向和幅度。基线可降低估计方差，但不自动保证训练稳定。多轮 Agent 的环境观察通常不由策略生成，不能把工具返回 token 当作模型动作去优化；应保存哪些 token 属于模型输出。

### 5.2 On-policy、离线训练与信用分配

**On-policy**强调使用当前或近期行为策略采样的数据进行更新；**off-policy**允许从不同于当前策略的数据学习，但需要考虑分布偏移，具体能否校正取决于算法。RL 系统常先固定旧策略采样，再对该批数据更新若干轮，策略越偏离旧策略，样本越可能过时。

**信用分配 credit assignment**：任务执行了 10 步最后失败，究竟第几步导致失败？只给最终 0/1 奖励信号稀疏、方差可能大；过程奖励或步骤验证能提供更密集信号，但标注不可靠时会把模型带偏。设计中可保留终局可验证结果、增加有证据的局部检查，并在独立任务上确认是否真的更好。

## 6. PPO、GRPO、DPO 和 RLVR

### 6.1 PPO：为什么有比例和裁剪

PPO 使用采样时的旧策略 `π_old` 作为比较；新旧策略在同一状态采样动作上的概率之比为：

\[
\rho_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{old}(a_t|s_t)}.
\]

常见裁剪目标是最大化：
\[
L^{clip}=\mathbb E_t\left[\min\left(\rho_t\hat A_t,\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)\hat A_t\right)\right].
\]

当优势为正、比例从 1 增大到超过 `1+ε` 时，目标中这项继续增大的激励被截住；当优势为负，向下变化超过边界也会受相应限制。例如 A=2、ε=0.2、ρ=1.5：不裁剪为 3，裁剪为 2.4，min 取 2.4。**裁剪不是对参数或 KL 的硬约束，也不保证任何动作概率绝不会越界。**常见 PPO 还用价值模型估计优势，可能加入熵项、价值损失或相对参考策略的 KL 惩罚，具体实现不同。

### 6.2 GRPO：一组回答提供相对基准

对同一问题采样 G 条回答或轨迹，获得奖励 `r₁,…,r_G`，一种常见的组内标准化优势为：
\[
\hat A_i=\frac{r_i-\operatorname{mean}(r_1,\ldots,r_G)}{\operatorname{std}(r_1,\ldots,r_G)+\varepsilon}.
\]

例如奖励 `[1,0,1,0]`，均值 0.5；按总体标准差 0.5 算，优势近似 `[1,-1,1,-1]`。一些实现采用不同标准差估计、归一化或损失汇总方式，不应把这个版本当唯一标准。优势随后用于类似比例裁剪的策略优化；部分方法或配置有 KL 项，不能断言所有 GRPO 都固定使用某个 KL 系数。

它常通过组内相对奖励避免单独训练一个价值网络，但增加多样本生成成本。若该组奖励全相同，组内差异为零，标准化优势为零，无法从这组奖励得到相对排序信号；增加探索、改变任务难度或改进验证器可能有帮助，但不是保证。多轮工具调用还要记录工具观察与模型生成的边界、隔离环境，并计算完整 rollout 成本。

#### 小练习：手算组内相对优势

```python
import math

def group_advantages(rewards, eps=1e-8):
    if not rewards:
        raise ValueError("rewards 不能为空")
    mean = sum(rewards) / len(rewards)
    variance = sum((x - mean) ** 2 for x in rewards) / len(rewards)
    std = math.sqrt(variance)  # 教学例使用总体标准差
    return [(x - mean) / (std + eps) for x in rewards]

print(group_advantages([1, 0, 1, 0]))
print(group_advantages([0, 0, 0, 0]))
```

这是计算优势的教学片段，**没有模型、环境、梯度或训练循环**；不同实现会使用其他标准差或归一化规则。

### 6.3 DPO：利用偏好对，不直接跑环境

给定问题 x、偏好回答 `y_w` 与不偏好回答 `y_l`，标准 DPO 损失的一种写法：
\[
L_{DPO}=-\log\sigma\!\left(\beta\left[
\log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)}-
\log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right]\right).
\]

σ 是 sigmoid，β 是与参考策略约束相关的系数，`π_ref` 是参考策略；对序列概率通常按其目标 token 的 log 概率求和，具体损失也有变体。直觉是使模型**相对于参考策略**更偏向被选中的回答。它可在预先准备的偏好数据上训练，不需要像在线 RL 一样每次更新都与环境交互；偏好来源、噪声与覆盖范围决定了它学到什么，轨迹的优劣也不一定只取决于最后一句话。

### 6.4 RLHF、RLVR、奖励投机

**RLHF**广义上利用人类反馈改善模型；一种常见流程是先收集人类偏好，训练奖励模型，再用 RL 优化，但不同流程可能使用 DPO 等方法。**RLVR**强调来自可验证规则或程序的奖励，例如数学答案检验、代码测试、任务状态校验；它可自动评分，不代表验证器覆盖了全部真实目标。

奖励示例：格式正确得 0.2、目标成功得 1、每次工具调用罚 0.01。若工具调用也能改评分脚本，模型可能直接篡改检查器；即使无法篡改，单靠格式奖励也可能学会输出漂亮但无效的答案。这是**奖励投机**。应保护验证器和环境，设置抗投机测试，跟踪奖励与独立成功率是否背离；要把安全约束设计在环境/权限中，而不只依赖奖励。

### 6.5 蒸馏：让学生学习教师的行为或分布

**知识蒸馏 distillation**让学生模型学习教师的输出信息，目标可能是用更小的模型、更低的调用成本复现某些能力。最简单的序列级做法：教师根据题目生成示范轨迹，经环境验证后作为学生的 SFT 目标；错误示范和未验证轨迹会给学生错误监督。

若能取得教师每一步的概率分布，还可对教师分布与学生分布计算 KL 散度等，让学生学习不仅是单一正确 token，也包括其他 token 的相对概率。这要求模型词表与对齐方式可处理，且要明确 KL 方向、温度和 mask。教师 API 往往不提供完整分布，无法假定一定能做 token 级蒸馏。

**离线蒸馏**可先保存一批教师轨迹再训练；一些**在线/在策略蒸馏（on-policy distillation）**方法让学生在自己产生的前缀或环境状态上获得教师指导，以减轻训练前缀与学生实际状态不一致的问题。具体 OPD 对教师输入、概率和损失定义并不统一，应查岗位使用的方法；学生生成的状态可能是错误或越权状态，仍须限制环境并验证。蒸馏、SFT 与强化学习可以结合，但并不等同：蒸馏的监督来自教师，RL 的优化信号来自奖励；二者都可能继承反馈源的偏差。参考[蒸馏原论文](https://arxiv.org/abs/1503.02531)。

## 7. 一次端到端 Agent 训练实验怎么组织

以“在若干笔记中找预算并引用”为例：

1. **定义任务**：给笔记库、问题、只读搜索与读取工具，目标是正确答案及可验证引用；规定调用和 token 上限。
2. **数据划分**：按文档家族划分 train/dev/test。记录模型、提示、工具、索引、题目与版本；防止同源改写题泄漏。
3. **基线**：同模型不训练，固定简单提示和工具；测成功率、引用支持、成本和失败切片。
4. **SFT**：准备经检查的调用/观察/答案轨迹，确认模板、mask、超长截断；用训练集优化，开发集选训练设置。
5. **RL（可选）**：固定环境和初始策略、每题多次 rollout；用独立保护的验证器检查答案与引用，记录每个模型生成段的 log 概率及 mask，按某明确实现更新策略。追踪训练奖励、独立成功、长度和工具次数。
6. **比较与消融**：对比无训练、SFT、SFT+RL；相同环境与足够明确的预算，重复采样并报告不确定性。分析新题与新文档家族，以及安全/通用能力是否退化。

这是一份**实验设计**，不是已经完成的实验。真实用 TRL、verl 等时需要核对具体版本、数据结构和软硬件；不能仅凭框架名认定支持某种多轮环境或声称自己已跑通。

## 8. 训练常见排错

| 现象 | 首先检查什么 | 后续验证 |
|---|---|---|
| loss 为 NaN | 全部标签被 mask、空序列、数值溢出、学习率、梯度 | 检查有效 token 数、logits/梯度有限性，最小批次复现 |
| loss 下降但任务成功不涨 | 模板/标签错、指标与目标错位、训练过拟合 | 解码样本，人工核对 mask 与工具执行；独立任务评测 |
| 工具调用格式对但执行失败 | 参数语义、权限、环境与接口版本 | 分类统计参数错误/工具不存在/真实执行结果 |
| RL reward 上升、真实效果下降 | 验证器漏洞、奖励尺度、数据泄漏 | 用独立隐藏测试和人工复核检查 reward hacking |
| 一组全零/全一 | 题太难/太易、验证器错、采样无多样性 | 按难度切片，校验 reward，不凭空加分 |
| 显存不足 | 长序列激活、batch、优化器状态、模型权重 | 先量峰值并缩 batch/序列；再考虑累积、检查点、LoRA/量化，需验证效果 |
| 训练中断 | checkpoint 不完整、外部环境状态不同步 | 保存权重、优化器、scheduler、随机状态、数据位置及版本；恢复后核验 |

**批次与梯度累积**：每卡 micro-batch 为 b、数据并行卡数为 n、累积 k 次时，有效 batch 近似 `b*n*k` 个样本；实际按 token 平均、丢弃不完整 batch、梯度同步等实现可能影响等价性。gradient checkpointing 通过重算中间激活换显存和计算，不等于任务恢复用的 checkpoint。
