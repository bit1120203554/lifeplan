# 知识、检索与上下文：让模型在正确的时候看到正确的信息

工具循环解决“怎么行动”，本篇解决“模型依据什么行动”。以问答为例：用户问“实验 A 的预算”，答案写在一百份实验笔记里。一次塞进全部笔记既贵又可能超过窗口；可以先找相关段落，再将问题和证据送入模型。

## 1. Prompt 与 Context Engineering

**Prompt**是给模型的任务说明及其输入。例如“根据提供的笔记回答，给出来源；找不到就说不知道”。常见结构是：任务目标、约束、所需输入、输出格式、例子。**零样本**不提供示例；**少样本**提供少量输入输出示例，但例子不等于额外训练，且可能引导错误模式。

**Context engineering**更广：设计每次调用时模型实际看到什么，包括系统规则、用户任务、历史、工具清单与返回、检索结果、摘要、预算及其排列。模型窗口能容纳多少 token 只是上限；长上下文仍可能有信息干扰、遗漏和费用/延迟问题。应按任务动态选择可验证的必要信息，并标注来源和时间。

例如用户要求对比两个版本：状态记录负责告诉模型各版本路径；检索负责提供对应变更；测试工具返回真实结果；提示要求模型区分“观察到的”与“推测的”。若只优化措辞却没有提供测试结果，不能期望模型知道真实测试是否通过。

**上下文压缩**：将旧历史提炼成摘要，保留目标、约束、已证事实、待办、来源与关键路径；摘要会丢细节，重要事实保留原始文件可回查。滚动窗口删除旧消息更简单，但可能丢失关键约束。每次压缩后需要检查是否将猜测误写为事实。

## 2. 记忆：存在哪里，何时取回来

| 名称 | 是什么 | 例子 | 主要风险 |
|---|---|---|---|
| 当前上下文 | 本轮模型能看见的消息 | 最近工具结果 | 丢失、超限、污染 |
| 工作状态 | 外部程序保存的当前任务数据 | 已完成/待做步骤、预算 | 过时、与真实外部操作不一致 |
| 长期记忆 | 跨任务可能有用的可检索记录 | 用户稳定偏好、成功经验 | 误记、泄露、过期 |
| 模型参数 | 训练得到的权重 | 已学到的语言规律 | 不是一次对话就会修改 |

长期记忆通常经历**提取→判定是否值得保存→写入并带来源/时间→按需检索→校验→更新或删除**。模型生成的“经验”是候选，最好经真实反馈验证；尤其不能将一次偶然成功写成无条件规则。RAG 更侧重从外部语料找当前需要的证据；记忆侧重跨交互保存有用状态，技术实现可能同样用数据库或向量检索。

## 3. RAG 全链路：构建与查询分开

**RAG（Retrieval-Augmented Generation，检索增强生成）**先从外部资料找证据，再将证据与问题一并交给模型生成。它能让模型使用最新、私有、或不能全塞进上下文的资料；质量仍取决于资料、检索、模型及验证。

**离线建库**：文档采集 → 提取与清洗 → 分块（chunk）→ 为每块保存原文、来源、权限、时间 → 建关键词索引和/或计算 embedding 建向量索引。这里的“离线”是相对查询阶段，可以定期或增量更新。

**在线查询**：解析问题 → 按用户权限过滤 → 关键词/向量召回候选 → 合并和重排 → 截取证据并保留引用 → 模型生成 → 检查回答与引用。模型只看到送入上下文的内容；索引命中但没送入上下文也无法利用。

### 3.1 分块为什么影响结果

块太小：一句结论与适用条件分离；块太大：无关信息多、难精准召回。按标题、段落、代码函数等语义边界切分；适度重叠可保留跨边界内容，但会引入重复和成本。表格、代码、PDF 需要相应结构处理。原文更新后须重建受影响索引，删除旧块。

### 3.2 关键词、向量、混合检索

**关键词检索**根据查询词和文档词的匹配程度排序，BM25 通常利用词频、稀有程度和文档长度，适合精确术语、型号、标识符。BM25 得分不是正确概率。

**Embedding**将文本编码成向量，语义相近的内容在向量空间中往往较接近。一个常用指标是余弦相似度：

\[
\operatorname{cos}(q,d)=\frac{q\cdot d}{\|q\|\|d\|}.
\]

例如 q=(1,0)、d₁=(0.8,0.6)、d₂=(0,1)，余弦分别为 0.8、0。它衡量方向相似，不证明事实正确。向量检索能匹配同义表达，但对编号、否定和精确数值可能不可靠；近似最近邻 ANN 用部分精度换速度，应评估召回损失。

**混合检索**分别获得词法和语义候选再合并。常见 RRF（倒数排名融合）不用直接加不同量纲的分数：

\[
\operatorname{RRF}(d)=\sum_i \frac{1}{k+\operatorname{rank}_i(d)}.
\]

`rank_i(d)` 是文档 d 在第 i 组结果中的名次，k 是平滑常数；未出现在某列表则该项通常记 0。例如 k=10，一个文档在两路分别排第 1、3，得分约 1/11+1/13=0.168。该数值是排序分数，不是概率。

### 3.3 重排与生成

召回阶段通常重速度，目标是找全可能相关的候选；**重排 rerank**对问题与候选作更细比较，目标是把最相关的内容排前面，可能使用 cross-encoder 或其他模型，成本通常更高。最后按上下文预算选取证据、去重、保留标题和可访问来源，提示模型根据证据回答。检索到相似文本不等于文本支持该结论；引用可点击也不等于引用真的蕴含答案。

下面仅示范 RRF，不实现完整 BM25、embedding 或检索服务：

```python
from collections import defaultdict

def rrf(rankings, k=60):
    if k < 0:
        raise ValueError("k 必须非负")
    scores = defaultdict(float)
    for ranking in rankings:
        seen = set()
        for rank, doc_id in enumerate(ranking, 1):
            if doc_id not in seen:  # 同一列表重复项只计第一次
                scores[doc_id] += 1.0 / (k + rank)
                seen.add(doc_id)
    return sorted(scores.items(), key=lambda item: (-item[1], item[0]))

print(rrf([["A", "B"], ["B", "A"]], k=10))
```

## 4. 出错时怎样区分检索与生成

假设问题的正确证据在文档 C：

- C 不在文档库：资料缺失或更新失败；调整索引也找不到。
- C 在库里但未进入 top-k：检查分块、查询、embedding、关键词、权限过滤与召回。
- C 在候选里但重排后丢失：检查重排、截断或 token 预算。
- C 已给模型但回答仍错误：检查指令、证据矛盾、模型理解、引用归因。
- 检索内容含恶意指令：把它当不可信数据，不能授予新权限。

**Recall@k**：带标注问题的所有相关证据中，top-k 找回的比例，常对每个问题计算后再平均。例：标注了 4 个相关块，top-5 找回 3 个，Recall@5=3/4。**Precision@k**=top-k 中相关块数/k；上例若 top-5 共 5 块、3 块相关，则为 3/5。标注不完整时这两个数会偏；多跳问题还应检查所有必要证据是否都找齐。端到端再看答案正确、证据支持率、引用质量、成本与延迟。评测方案见[评测与工程](evaluation-engineering.md)。

### 4.1 Agentic Search：多轮检索什么时候有意义

一次性 RAG 通常是“问题→检索→生成”；**Agentic Search**允许系统根据检索结果判断是否还缺证据，改写查询、调用其他来源或继续查找，再决定何时停止。例：需要比较两个实验，第一次只找到 A，则检索 B；如果两份笔记互相矛盾，继续查版本和日期，而不是把第一份结果当最终事实。

常见循环：明确子问题 → 选择检索工具或查询 → 观察候选及来源 → 判断是否足够、是否矛盾 → 必要时再查 → 输出带依据的答案。查询改写可能引入新歧义，多轮也增加成本并可能越查越偏；应设置最大次数、可信来源、证据充分条件与超时。检索质量指标之外，还应评估**任务最终成功率、引用支持率、调用次数和成本**。Agentic Search 与游戏树搜索都是多步寻找信息或行动，但检索结果不一定是可回滚模拟器，不能把相似度当作可靠状态价值。

### 4.2 多模态检索与记忆

图片、音频、视频也可以有各自的 embedding 或结构化描述，查询可能跨模态，如用文本找图片。实际链路需要记录原媒体、帧/时间范围与来源，避免只用一段模型生成的图片描述作为事实。不同编码器、模态和分块策略的相似度未必可直接比较。多模态记忆同样面临权限、更新、时效和错误回写问题。

## 5. 上下文与记忆的工程取舍

- 先找权威和近期来源，保留版本；冲突时呈现差异而非把多段文本硬拼。
- 对用户文档先权限过滤再检索/返回；不能因为相似就泄露其他用户的数据。
- 不把整个历史工具输出无限追加；可保留结构化状态和指向原记录的 ID，按需回查。
- 长期记忆记录来源和生效时间；用户更正要支持删除/更新。
- 对话有私有数据时控制记录、脱敏和保存时间；语料变化后做回归检验。
