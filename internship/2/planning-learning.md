# 规划、反馈与学习：怎样让 Agent 的行动逐步变好

这篇连接你研究中熟悉的环境、搜索、程序和实验。关键区分：**模型在一次任务里根据新观察改变回答**、**更新外部程序或记忆**、**训练改变模型参数**是三件不同的事。前两种不必训练 NLP 模型，但仍需要可重复验证。

## 1. 把任务写成状态、行动、观察和目标

状态 s 描述当前情况；行动 a 改变环境或请求信息；观察 o 是环境返回给 Agent 的可见信息；目标定义什么叫完成。真实环境可能部分可观测：Agent 只看到网页的一部分，不知道服务器内部状态。工具调用是动作，返回的报错也是观察。

例如推箱：状态含地图、玩家与箱子位置；行动是移动；模拟器给出新状态或非法动作；目标为所有箱子在目标点。另一个例子是代码修复：状态包含仓库、测试结果；行动是读文件、修改、运行测试；目标需由测试和任务约束共同定义。

**预算**可能包括模型 token、调用费、环境交互次数、搜索展开、墙钟时间。行动对环境有副作用时，探索或反复试错可能不可逆，需要安全沙箱、用户确认或只读预演。

## 2. 规划、执行、验证为什么要分开

规划提出一组未来步骤；执行实际改变环境；验证检查当前状态是否满足目标。一次性规划适合流程明确、变化少的任务；当网页状态变化或工具报错，就需要根据新观察调整。模型生成的计划只是候选，不能当成已经执行。

**ReAct**把决策、动作和观察交替：搜索信息 → 读结果 → 判断缺什么 → 再调用工具 → 回答。适合问题逐步明确的情形，但可能循环调用、受错误观察误导；限制步数与预算，并设计证据检查。

**反思 reflection**是让系统依据反馈形成修正假设，例如“这条程序在箱子靠墙时出错”。有效闭环需要：真实输入 → 实际执行 → 可观察的错误 → 候选修订 → 独立测试。模型自称“我已修复”并不是验证；同一个模型检查自己也可能重复偏差。一个测试没通过不等于解释已确定。

### 2.1 单智能体、多智能体和任务分解

一个 Agent 可以自己完成“搜索→写代码→验证”；也可以由主 Agent 分配给检索、实现和测试等子 Agent。**子 Agent**通常有各自的上下文、工具权限及任务目标；**多 Agent**描述多个执行体的协作方式。常见分工包括：

- 主从：主 Agent 分解任务、分派子任务、汇总并验证；适合相对独立的工作。主 Agent 仍要判断子结果是否可靠。
- 并行候选：多个 Agent 解同一题，验证器选解；适合可验证任务，但重复调用有成本，候选错误可能高度相关。
- 流水线：一个产出候选，另一个检查或执行，失败则回退；如果检查与生成共享偏差，不能把相互赞同当作事实证明。

要定义每个子任务的输入、可用工具、可写区域、产物格式、预算、超时、终止和汇总规则；共享文件时可能覆盖彼此修改。独立问题可并行，有数据依赖的步骤则需等待。比较多 Agent 与单 Agent 时控制模型、工具和总预算；角色数增加不保证效果增加。

### 2.2 面向不同应用，行为和评价重点不同

**Coding Agent**读取仓库、定位问题、修改代码、运行测试；除了最终测试，还要核实是否解决用户描述的问题。**Browser/GUI Agent**基于页面、截图或可访问性树观察，输出点击、输入等动作；页面变化、元素定位、权限与不可逆操作是关键风险。**Research Agent**提出检索计划、收集证据、组织引用；新观点和证据需分清。它们共享动作—观察循环，但不同环境的工具、可见状态、验证器和风险不同。

像研究中的规则模拟器，可能可以安全地复制并重放状态；网页付款或修改线上数据库通常不具备这个性质。设计搜索和反馈时，要先判断环境是否可复制、重置、并发和验证。

## 3. 搜索：为什么试多个候选，试多少

当一个决定可以分支成多个动作时，搜索通过模拟或执行比较候选。例如初始状态有 A、B 两个动作，单条贪心轨迹可能漏掉需要先绕路的解；搜索维护多个分支，代价是更多模拟和内存。

- **BFS**按层扩展，在每步成本相同且满足相应条件时能找到最少步解，但分支多时内存开销大。
- **DFS**优先沿一条路径深入，内存通常较省，但可能先钻进无效路径；深度上限和去重需设计。
- **A\***用 `f(n)=g(n)+h(n)` 排序，g 是起点到当前的已知成本，h 是剩余成本估计；最优性取决于非负边成本等条件及启发式的可采纳性/一致性、重复状态处理，不能说任何启发式都保证最优。
- **MCTS**多次执行选择、扩展、模拟/估值、回传，以预算逐步比较分支；有限预算内的统计可能非常不确定。

PUCT 常见形式为
\[
a^*=\arg\max_a\left[Q(s,a)+cP(s,a)\frac{\sqrt{\sum_bN(s,b)}}{1+N(s,a)}\right].
\]
Q 是已估计的行动价值，P 是先验偏好，N 是访问次数，c 决定探索项权重。具体初始化与价值尺度随实现而异；P 来自 LLM、规则或网络均可，但先验错误可能反复引导搜索。有限预算没找到解仅表明**本次搜索未找到**，不能推出无解。真实昂贵或不可回滚环境不能随便当成免费模拟器。

## 4. 测试时计算与反馈来源

**Test-time compute（测试时计算）**指推理/执行阶段花额外算力或调用预算以改善结果，例如采多个候选、搜索、调用验证器、修正错误。比较时应同时报告成功率、模型调用、token、环境交互、时间和费用；有时多次采样的提升只是花了更多预算。

反馈来源可分：

1. **可执行验证器**：编译、单测、合法性检查、环境奖励；可复现，但测试可能不覆盖真正目标。
2. **外部观察**：工具输出或用户反馈；可能不完整、噪声大或有延迟。
3. **模型评判**：模型按 rubric 打分；适合开放式答案，但要与人标或可靠规则校准。
4. **人类审核**：能处理复杂语义，但昂贵、标注也可能不一致。

重要区别：产生候选的模型与负责判断的模型，即便是不同模型，也可能共享偏差。与其只问“有没有 judge”，要问判定依据、校准和误判率。详见[评测](evaluation-engineering.md)。

## 5. 经验复用、自进化与模型训练

可设计一种外部经验循环：从历史任务中挑选片段 → 生成候选规则/代码 → 检验合法性与局部行为 → 在训练/开发任务筛选 → 冻结版本，在未见测试任务中评估。要记录生成方式、工具预算、失败和回滚，防止把开发集上反复调参的结果当泛化。

- **外部更新**：修改提示、记忆、工具代码、策略库或搜索超参；模型权重可始终冻结。
- **参数更新**：基于数据与目标函数改变模型/学习器权重，如 SFT 或 RL。
- **自进化**是宽泛说法，必须说明谁生成候选、由谁验证、更新了哪部分、在哪些独立任务上证明有效；不是“模型反思一次就会学习”。

模型参数训练中，SFT 使用示范，偏好优化使用优劣样本，RL 使用采样反馈；数据、损失及更新对象不同。轨迹可以用于分析或训练，但**收集轨迹不自动等于训练过模型**。完整内容、公式和排错集中在[Agent 数据与大模型训练](model-training.md)，避免在这里重复一套。

## 6. 联系你的研究，怎样如实讲

**I001 / Id1**关注规则已知、可模拟的稀疏长程任务：希望模型结合调查、局部验证和搜索，形成可执行、可复用策略；当前方法仍在设计和验证，LLM 参数冻结。其困难是预算内获取可靠信号，以及怎样把搜索状态/后果转化为模型可理解和可检验的依据。它与 Harness 中的环境接口、预算管理、轨迹、检查点和 verifier 有共同问题，但不能直接说研究已解决这些难题。

**I003 / Id3**探索参数学习与可解释程序共同改进决策；当前是候选方案和原型检验。局部程序生成、搜索证据、有限对照可作为讨论；不应宣称已经证明闭环收益或等同通用 LLM 后训练。旧 4a 已停止，旧实验属于其特定设置，不能拿来证明新方法有效。

面试可以说：“我关注怎样把模型的候选想法接入可执行环境，用反馈区分有效与无效，再控制预算评估是否可复用。当前在探索阶段，我会先用简单基线与冻结测试来检验。”实际跑过什么、由哪些工具辅助、失败情况、成本与局限应按具体记录如实补充。不要把熟悉问题表述成已经熟练使用某框架。
