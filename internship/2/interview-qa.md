# Agent 面试问答：先理解，再练习表达

这些是参考回答，不是本人已经掌握或做过的经历。每题先尝试 1 分钟口答，再回正文核对机制；若被问实践，明确区分已运行、研究计划和教学例子。

## 基础与系统

**1. Agent 和普通对话有什么区别？**

普通对话可以只根据输入生成回答；Agent 系统让模型参与选择行动，通过工具与环境交互，读取结果并继续，直到达到目标或预算上限。执行、权限、状态和结束条件由外部程序与模型共同配合；模型说“我已经做了”需用工具结果验证。

**2. Agent Harness 是什么？**

它是承载模型完成任务的外部运行体系，包括上下文组装、循环、工具接入、状态与检查点、权限、错误恢复和评测等。名称边界因团队而异。假设模型建议读文件，Harness 验证路径、执行读取并把内容返回；它的质量会影响同一模型的任务成功率。

**3. Function Calling 的完整过程？**

应用提交工具名称、用途和参数 schema；模型提出结构化工具调用；应用解析并校验参数、权限后执行；将真实结果通过对应调用 ID 作为工具消息返回，再请求模型继续或结束。JSON 格式正确不代表授权、业务条件或内容正确；对于写操作需额外处理重复执行。

**4. 工具调用出错后怎么处理？**

先区分参数不合法、权限拒绝、工具业务失败、服务超时等，把可理解的错误反馈给模型并限制重试。只读临时故障可有限退避重试；有副作用的操作超时可能已经成功，需幂等键或查询状态，不能盲目重复。记录轨迹并设时间、费用与步数上限。

**5. Agent 和 workflow 怎么选择？**

步骤明确且稳定可先用固定流程，便于测试和控制；步骤需要根据观察变化时可用 Agent 决定局部动作。两者可混合，比如固定先检索、再让 Agent 选择补查。比较应看成功率、复杂度、成本、风险和维护负担，而不是默认越自主越好。

**6. ReAct 是什么？**

让模型的决策、外部动作和观察交替进行：查资料、读结果、判断缺口，再选择是否继续。它把决策建立在环境反馈上，但仍可能错误选择工具或无限循环，需要预算和独立验证；不要求公开模型内部推理内容。

**7. MCP、Function Calling、Skill 有什么区别？**

Function Calling 是模型生成结构化工具调用请求的方式；MCP 是客户端和服务端发现、调用工具及访问资源的一套协议；Skill 常是按需加载的任务指导及资源。模型调用可由运行器通过 MCP 执行，但安全权限要独立检查；不同产品的 Skill 行为不完全相同。

**8. 如何防止 Prompt 注入？**

工具输出和网页都是不可信数据，即使它们写“忽略之前指令”也不能赋予权限。使用最小权限、隔离执行、参数验证、外部操作独立授权、输出限制和日志审计等多层防护；仅靠提示不能保证安全。再用恶意输入测试越权、泄露、错误工具调用等情况。

## 上下文与检索

**9. Prompt engineering 和 context engineering 的区别？**

Prompt 关注任务说明、约束及示例怎么写；context engineering 还决定每次调用看到哪些历史、工具说明、检索证据、状态和摘要，以及它们的组织与预算。长文本并不保证正确检索；应保留来源和关键状态，按需回查。

**10. RAG 全流程是什么？**

建库时采集清洗、分块、保存来源与权限、创建词法或向量索引；查询时按权限召回候选、合并和重排、在预算内装入证据，再基于证据回答并检查引用。召回不等于回答正确：可分别检查证据是否入库、是否召回、是否进入上下文、生成是否受支持。

**11. 向量检索和关键词检索有何不同？**

关键词常依赖词项匹配，适合编号和精确术语；向量把文本映射到语义空间，适合不同表述但可能忽视数字或否定。可混合召回再重排；相似度不是事实正确概率。分块、索引更新、权限、评测标注同样影响结果。

**12. 什么是上下文与长期记忆？**

上下文是模型本轮能看到的输入；长期记忆是外部跨轮保存、按需取回的信息。一次对话中加入记忆不等于修改模型权重。记忆应有来源、时间、检索、更新和删除机制；压缩有丢失细节与错误固化风险。

## 搜索、学习与研究

**13. 怎么评价 Agent 的反思有没有用？**

让它基于实际失败观察提出可检验的修改；在保留条件下执行并评估，记录预算和失败。与不反思、等预算增加采样等基线比较，并在未参与修改的任务上冻结测试。模型自评变好了不是收益证明。

**14. 搜索为什么有帮助，有什么边界？**

搜索保留并比较多个行动路径，减少贪心决策遗漏；BFS、DFS、A*、MCTS 使用不同扩展策略。它要消耗算力与模拟预算，结果依赖环境及评分可靠性；有限预算没找到解只能说明本次未找到，不能推出无解。

**15. 外部自进化和训练大模型有什么区别？**

修改外部提示、记忆、代码或策略库可以不改变模型权重；SFT/RL 等则更新参数。介绍自进化应说明候选由谁生成、如何验证、具体更新什么、预算和独立测试结果。我当前研究仍在探索，不把设计目标说成已验证效果。

**16. SFT、RL、DPO 分别是什么？**

SFT 用示范输出做监督学习，通常对目标 token 计算负对数似然；RL 根据采样行动及奖励改策略，效果依赖奖励和采样；DPO 利用偏好回答对及参考策略训练。三者的数据、优化对象和验证方式不同，不能只靠术语说明自己有训练经验。

## 评测与工程

**17. 怎样评测 Agent？**

明确任务集、初始环境、可用工具、预算和成功标准；记录完整轨迹及最终环境状态。组合规则验证、模型评分和人工抽检，分别看任务成功率、工具错误、成本、延迟与安全。固定版本与对照，做失败切片并在独立测试集复验。

**18. LLM-as-a-Judge 有哪些问题？**

它能按 rubric 处理开放式评价，但可能受答案位置、长度和模型风格影响，也可能误判事实。要用人工标注样本校准、交换回答顺序、抽样复核，并尽可能结合可执行验证器。Judge 评分不是客观真值。

**19. pass@k 与成功率有何区别？**

pass@k 衡量一个问题产生 k 个候选时至少一个正确的可能性；任务成功率关注实际任务运行是否成功。如果生成 4 个有 1 个正确但最终选了错误答案，候选覆盖与最终系统表现不同；多次采样的 token/费用也必须计入。

**20. 线上工具调用成本高、延迟高，怎么定位？**

先按 trace 切分模型、检索、工具和重试耗时；统计输入输出 token、调用次数、p50/p95。然后针对瓶颈尝试减少无用循环、优化检索和上下文、合理并行独立调用或缓存，并用成功率和安全指标监控回归。不能只压调用次数而不看质量。

**21. 如果任务需要执行模型生成的代码，如何设计？**

先判断是否确有必要，尽量在隔离的受限环境执行，控制文件、网络、权限、资源和时长；校验输入输出，保留日志。对可产生外部副作用的操作实施额外授权；超时、异常和恢复要处理，容器默认配置不能自动当作完整安全保障。

**22. 怎么利用研究经历匹配 Agent 岗？**

我有从建模到实验分析的研究经验；现在关注模型如何利用环境反馈产生与检验可执行策略，以及有限预算下的规划。这与 Agent 工具、验证和评测问题有关联。当前方案仍在原型和探索阶段，我会清楚说明实际做过的组件、失败和尚无证据的部分；具体实践及使用工具按真实经历说明。

## 设计与手写练习

**23. 设计一个能查笔记回答问题的 Agent。**

定义只读 `search`/`read` 工具和 schema；运行器接模型、检查调用并返回带 ID 的结果；限制步数、时间和范围。检索结果保留来源，模型回答时给出支持证据，不足则说明。测试覆盖查无内容、错误参数、矛盾文档、注入、超时与越权；指标看正确率、引用支持率和成本。可从[最小循环代码](agent-harness.md)扩展，它目前只是模拟模型。

**24. 为研究中的策略候选设计评测。**

用固定环境与相同预算比较旧规则、简单固定基线、候选规则；区分开发任务与独立测试任务。记录成功、模拟次数、模型调用及失败原因，检查非法动作与过拟合。候选如借助工具生成，要记录生成和筛选成本；先得到结果再下结论。

**25. 手写工具循环时要有哪些关键判断？**

解析模型响应，区分最终答案和工具调用；白名单检查工具与参数，执行并捕获错误；以调用 ID 返回真实结果；每轮检查最大步数、超时或预算。真实接口要适配供应商消息格式、多调用和持久状态。完整可运行示意见[Agent 与 Harness §3](agent-harness.md)。

**26. 写检索融合或统计成功率时注意什么？**

RRF 对每路名次计算倒数后求和，分数不是概率；一个列表的同一文档应去重。成功率要明确分母是运行还是任务，多次试验不能当作独立任务数；空输入应有定义。示例见[检索 §3](context-rag.md)与[评测 §5](evaluation-engineering.md)。

## 模型训练、数据和拓展方向

**27. SFT 的输入、目标与 loss mask 是什么？**

SFT 使用输入与示范输出，让模型预测输出的下一个 token，用负对数似然训练。多轮工具轨迹里，用户消息和工具返回可作为上下文，常把它们的损失屏蔽，仅训练助手的工具调用与回答；具体依目标配置。必须按模型的聊天模板编码，检查 logits 与下一 token 的标签对齐，避免所有标签被屏蔽。

**28. 工具调用数据怎么做成训练样本？**

记录任务、可用工具 schema、助手请求、工具真实返回和最终答案，保留调用关系和环境版本。检查参数、结果、敏感数据和成功判据，按任务家族划分训练/测试；正确关联每段助手目标的 loss mask。模型伪造的工具成功不能当作真实观察。

**29. LoRA 为什么省显存？能减少所有显存吗？**

冻结原始权重，为选中矩阵训练低秩增量 BA。若原矩阵为 `d_out × d_in`，适配器参数量是 `r(d_in+d_out)`，通常远小于原权重；因此训练梯度和优化器状态更少。但基础权重、激活等仍占空间，不能按参数比例推断总显存。QLoRA 还量化冻结基座，但计算和适配器精度取决于实现。

**30. 强化学习的策略、回报和优势各是什么？**

策略是状态下行动的概率，奖励是环境反馈，回报是之后奖励的折扣和。价值是未来回报的期望；优势衡量某行动相对状态基准好多少。策略梯度利用采样动作的 log 概率梯度与优势调整策略；奖励定义不准会把模型引向错误目标。

**31. PPO 的裁剪项做什么？**

它比较当前与采样旧策略的动作概率比，对优势加权后的目标使用裁剪，降低过大概率变化带来的优化激励。对于正优势，概率比超过上边界后，目标不会继续按同样方式奖励其增长。它不构成严格的参数或 KL 硬约束，其他项、学习率和采样设置仍会影响稳定性。

**32. GRPO 组内全是零奖励怎么办？**

全相同奖励的组没有组内相对差异，常见的标准化优势为零；先检查验证器是否正确，以及任务是否过难、采样是否缺多样性。可尝试调整任务难度、冷启动或奖励设计，再评测是否真正改善；不能凭空增加容易被利用的奖励。组采样和环境交互成本也要报告。

**33. DPO 与 RL 有什么区别？**

DPO 通常用给定输入下的优劣回答对，使策略相对参考策略更偏向被选回答；其标准离线流程不用每次参数更新都在线与环境交互。RL 则依据奖励与策略采样优化；两者都可能受反馈质量和分布限制，不能说 DPO 保证事实正确。

**34. 多轮 Agent RL 的难点是什么？**

一条轨迹交错模型输出和工具观察，只对策略生成部分计算相应策略损失；环境需要可重置、验证器可靠，记录策略版本、耗时和预算。长程稀疏奖励带来信用分配难题，过程奖励可能有偏。外部调用慢、失败或有副作用也会影响采样与安全。

**35. RLHF、RLVR 与 reward hacking 怎么理解？**

RLHF 利用人类反馈，常见做法包括偏好数据和奖励模型；RLVR 使用程序或规则可验证的反馈。奖励投机是模型获得高分却偏离真实目标，例如只满足输出格式。要保护验证器，采用独立隐藏测试并比较真实成功率与训练奖励。

**36. 为什么训练 loss 下降但 Agent 任务成功率没有提高？**

可能学到格式而非真实决策、训练轨迹和测试环境分布不一致、标签/工具结果错误或验证标准不同，也可能过拟合。先解码若干数据检查模板与 mask，分工具选择、参数、执行和结果阶段评测，再用独立任务集和训练前基线比较。

**37. Agentic Search 与一次 RAG 的区别？**

它允许模型根据检索反馈继续查询、改写问题、处理冲突并决定何时停止；一次 RAG 通常只做一轮检索和生成。多轮有利于逐步补证据，但也会放大检索错误并增加成本，应设置来源、停止条件与预算。

**38. 多 Agent 一定优于单 Agent 吗？**

不一定。任务独立时可以并行分工，检索和测试也可用不同角色；但会出现重复开销、错误共识、冲突写入和汇总丢失。需要明确子任务、权限和验证方式，在相同总预算下比较单 Agent 基线。

**39. GUI Agent 和文本工具 Agent 有哪些不同？**

GUI Agent 可能从截图、页面结构或可访问性树感知，再输出点击、输入、滚动；页面变化和定位错误会影响操作，外部写操作也可能不可逆。文本工具 Agent 通常用结构化函数调用，但仍有授权和数据真实性问题。两者都应验证动作后的实际环境状态。

**40. 没有训练过 NLP 模型，面试被问时怎么办？**

如实说自己的训练经验主要来自视觉模型，理解数据、损失、梯度与实验对照；语言模型部分正在系统学习 token、SFT、工具轨迹和 RL。随后讲自己真实做过的训练与调试，以及希望如何迁移，不能把阅读文档或教学例子说成跑过大模型训练。
