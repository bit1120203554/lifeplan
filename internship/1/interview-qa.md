# AI Infra 面试题与答案

本题库针对两次面试中暴露的主题，结合公开论文和官方文档自行编写；**不是已验证的真实面试题或题频统计**。建议先看题目、独立口述，再展开答案。每题给出原理和必要边界，P0 先练，P1 用于深入。

## 注意力演进：Q01—Q10

### Q01 [P0] 注意力解决什么问题？Q、K、V 是什么？

当前 query 与各位置的 key 比较，得到各位置的权重，再加权读取各位置的 value，使当前位置能从上下文选取相关信息。Q 是查询表示，K 是被匹配的表示，V 是读取内容，三者通常由输入经可学习投影得到。softmax 沿可见 key 位置归一化；因果语言模型还必须屏蔽未来位置。注意力输出是加权和，不是简单选择一个 token。

### Q02 [P0] 为什么提出多头注意力？是不是把原向量直接切成几份？

不同头使用不同的学习投影，允许模型同时在不同表示子空间和不同位置上聚合信息，最后把各头输出拼接、投影。每个头的投影可以依赖原始 D 维向量的全部输入；不能说每个头只看到被硬切出来的一段输入维度。

某些头可能学到不同关注模式，但没有保证每个头承担固定可解释语义。固定总宽度时头宽通常为 D/H；不能说头越多就必然更强或更快。[模型与注意力](model-attention.md#attention)

### Q03 [P0] MQA 和 GQA 分别为了解决什么问题？

自回归 decode 需要缓存并反复读取各层历史 K/V，长上下文和高并发下其容量与带宽成为潜在瓶颈。MQA 让多个 Q 头共用一个 KV 头，GQA 让每组 Q 头共享一个 KV 头，以降低 KV 的投影、存储及潜在读取成本。MQA 共享较强可能造成质量损失，GQA 提供折中；效果需结合模型和任务验证。

### Q04 [P0] Hq=8、Hkv=2 时怎么分组？共享后输出一样吗？

每 4 个 Q 头共享一组 KV：Q0—Q3 用 KV0，Q4—Q7 用 KV1。即便 Q0 和 Q1 使用同一个 K/V，它们的 Q 也可不同，因此匹配分数、softmax 权重及输出都可不同。最后仍拼接 8 个 query 头的结果。

### Q05 [P0] KV cache 大小怎样算？GQA 为什么不保证速度同比例提升？

相同长度 T、B 条请求的普通 KV payload 近似 `2LBT Hkv d s` bytes；2 为 K 和 V，L 层数、d 头宽、s 每元素字节。Q=32 头、KV=8 头时，其他条件一致，缓存是 32 KV 头的 1/4；具体例子 32 层、T=4096、d=128、2 bytes 为 512 MiB。包含权重、尾块、量化元数据的总显存不会按 KV 比例变化。

Q 头仍需计算注意力；权重、通信、调度可能成为瓶颈。若实现将 KV 物理重复或不能复用读取，节省也可能打折。改变已有模型的头数通常涉及权重转换及继续训练，不是无损开关。[GQA 的代码和参数](model-attention.md#gqa)

### Q06 [P0] 朴素 attention 的中间矩阵有哪些？FlashAttention 如何分块并得到全局 softmax？

**哪些矩阵占显存？** 普通 attention 先计算分数矩阵 `S=QKᵀ/√d`，再计算概率矩阵 `P=softmax(S)`，最后得到 `O=PV`。序列长度为 T 时，单个头的 S 和 P 都有 T×T 个元素。一种朴素实现会把完整 S、P 分别存入 GPU 设备显存（如 HBM），供后续计算读取；长序列时，它们既占空间，也带来大量显存读写。具体实现可以融合操作，不是所有实现都会逐步保存这两个完整矩阵。

**FlashAttention 如何分块并算对全局 softmax？** 它把 Q、K、V 分块，从设备显存读入更小、更快的 GPU 片上存储，计算当前块的分数和 V 的贡献；对每个 query 维护已经处理过的分数最大值 `m`、指数和 `ℓ`、未归一化的加权和 `u`。新块到来时，若最大值发生变化，就先把旧累计量缩放到新的最大值基准，再加入新块的贡献。所有块处理完后，用 `u/ℓ` 得到输出。这样避免在设备显存中保存完整 S 和 P；最终输出 O 仍会存入显存。

**为什么各块单独 softmax 再平均不对？** 每块单独 softmax 时，其概率和都会变成 1，原本不同块在全局分母中的权重就丢失了。例如分数 `[0, ln2]` 和 `[ln4]` 是两块，对应 V 为 `[10,20]` 和 `[30]`：两块各自的输出约为 16.67 和 30，直接平均为 23.33；而全局 softmax 给三个位置的权重比例是 1:2:4，正确输出为 `(10+40+120)/7≈24.29`。

**计算量变了吗？** 标准 dense 全注意力仍要计算所有允许的 query–key 关系，算术量仍约为 `O(T²d)`，没有变成线性。FlashAttention 主要减少完整中间矩阵的存储和设备显存读写；训练反向还可以重算部分局部量，以计算换存储。具体公式见 [FlashAttention 完整讲解](model-attention.md#flash)。

### Q07 [P0] FlashAttention 和线性 attention 有何根本区别？

FlashAttention 侧重相同 dense softmax 计算的分块与设备内存读写；线性 attention 用可分解的核、递推状态或近似等方式，避免显式对所有位置逐对算 softmax。在特征维等固定时，其计算可以对序列长度呈线性，但往往改变或近似标准 attention，质量和常数开销需验证。不能因为 Flash 不保存 T² 矩阵就说它算术复杂度线性。

### Q08 [P1] 线性 attention 为何能先汇总 K/V？softmax 能直接移除吗？

如果相似度核可写为 `φ(q)ᵀφ(k)`，先累积 `S=Σφ(kⱼ)vⱼᵀ`、`z=Σφ(kⱼ)`，再算 `o=φ(q)ᵀS/(φ(q)ᵀz)`。展开求和可得到同一个核的逐项加权结果；因果模型每来一个 token 先更新 S 和 z。固定特征维 r 和 value 维时，其状态大小不随 T 增长。

普通 softmax 的 `exp(qkᵀ)` 不可直接用矩阵乘法结合律改成 `Q(KᵀV)`；选用非负核一般改变目标，Performer 等则用特征近似 softmax 核。[线性注意力](model-attention.md#linear)

### Q09 [P1] 窗口、稀疏、MLA 和 Ring Attention 分别改了什么？

窗口/稀疏 attention 改变可直接访问的位置对，以减少计算，但可能失去直接全局连接。MLA 通过低维潜变量压缩 KV 表示，降低缓存成本；实际设计还需要考虑位置编码。Ring Attention 沿序列分卡、让 KV 块在卡间传输，本地 Q 聚合跨块结果；它分摊存储和计算，不自动消除全局 dense 的二次算术量。

### Q10 [P1] 线性 attention 的常数大小状态有什么限制？

在简单因果线性核示例中，状态把历史压缩成固定形状的 S 和 z，不能像保存逐 token KV 一样直接读取任意旧位置；长序列下信息容量、精度和质量要测试，任意 mask 或滑动删除也需要额外机制。整个训练过程的显存还包含反向激活等，不能由推理状态固定就声称训练显存恒定。

## Prefill／Decode 分离：Q11—Q18

### Q11 [P0] Prefill 和 Decode 分别做什么？D 何时进入 KV？

对 prompt A/B/C，prefill 处理这些已知 token、建立各层 K/V，最后位置 logits 可以采样出首个新 token D。D 被送入下一次模型前向后才计算并追加自己的各层 K/V，再得到下一 token E。decode 依赖此前生成的 token，普通自回归方式需要逐步推进。[推理服务](inference-service.md)

### Q12 [P0] 为什么将两阶段分开部署？

长 prefill 常有大量并行计算，而 decode 每请求每步通常只有一个新 token、涉及权重与历史 KV 读取；同池调度时长 prefill 可能使已有 decode 请求的 token 间隔增大。分离让 P、D 资源和并行策略可分别配置，降低直接干扰。但这是工作负载相关的工程取舍，不保证任意情况下 prefill 都算力受限、decode 都访存受限。

### Q13 [P0] P/D 分离时 P 向 D 交接什么？

通常要让 D 获得继续计算所需的各层前缀 KV、位置／长度与请求状态；并行布局或 dtype 不同时可能还要转换或重分片。首 token 可由 P 端采样后返回并交给 D 继续，也有不同系统时序。若 P 已采样 D，前缀 KV 仍只含 prompt，D 要作为下一次输入计算自己的 K/V。

### Q14 [P0] 假设 KV 为 512 MiB、网络有效单向 25 GB/s，传输要多久？

`(512×2²⁰) / (25×10⁹)≈0.0215 s=21.5 ms`，这里分母是 25,000,000,000 bytes/s。仅是理想数据传输下限，不含排队、建连、设备搬运、协议、同步或格式转换。并发迁移会共享带宽。若首 token 已先返回，这部分等待可能体现在首、第二 token 的间隔；是否进入 TTFT 由实际时序决定。

### Q15 [P0] Chunked prefill 和 P/D 分离是同一件事吗？

不是。Chunked prefill 把长 prompt 的计算切成较小片段，让调度器可以在同一资源池中交错安排 decode；P/D 分离是不同实例／设备处理两个阶段，需要交接前缀状态。二者可以组合，分离也不是天然优于合理调度的同池系统。

### Q16 [P0] 分离的代价有哪些？一定提升吞吐吗？

可能多一份或多组模型权重、KV 传输和重排、跨池排队、资源配比与容错开销。两侧需求不平衡时一边可能繁忙而另一边空闲，迁移也可能增加 token 间隔。针对某些负载可改善尾延迟和 SLO goodput，但不能保证原始吞吐、TTFT、TPOT 一起改善。对照应固定 GPU 数、模型、输入输出分布和负载。[推理服务](inference-service.md)

### Q17 [P0] TTFT、ITL、TPOT、goodput 是什么？

TTFT 是请求发起到首 token；ITL 是相邻输出 token 间隔；TPOT 常按首 token 后生成耗时除以后续 token 数，但具体口径必须说明。Goodput 是满足指定 SLO 的有效请求或 token 速率，单位与阈值要明确。例：首 token 100 ms，第二、第三 token 在 130、160 ms，则 ITL 各 30 ms，按此定义 TPOT=30 ms。

### Q18 [P1] 分离后首 token 快但第二个 token 很慢，如何查？

沿时间线拆分 P 完成／首 token 返回、KV 排队和传输、布局转换、D 端接收及队列、首次 decode 和网络返回；同时看链路带宽、并发和资源负载。若 KV 很大或 D 池排队，瓶颈可在交接而非 P 的模型计算。先测量再调传输、并发或资源比例。

## vLLM 与服务工程：Q19—Q30

### Q19 [P0] vLLM 是什么，一次请求经过哪些部分？

vLLM 是大模型推理与服务引擎，提供离线批量生成及在线 API 等能力。请求经接口校验与分词进入引擎，调度器选择本轮执行的请求/token，worker／模型执行前向并管理 KV，采样得到 token，随后更新状态并返回结果。实际进程结构和具体 API 随版本、配置变化；它不是模型结构本身。[推理服务](inference-service.md)

### Q20 [P0] PagedAttention 是什么？和 FlashAttention 一样吗？

PagedAttention 将请求 KV 按块管理，并通过块表将逻辑块映射到物理缓存块，注意力读取对应块，缓解连续预留和碎片。FlashAttention 主要通过分块计算及在线 softmax 优化注意力中间矩阵和显存读写。前者关注 KV 管理／访问，后者关注 attention 计算；能否同时使用由后端与模型支持决定。

### Q21 [P0] 块大小 4、块表 [7,2,9]、位置 9 如何寻址？

逻辑块 `9//4=2`，偏移 `9%4=1`；查块表得到物理块 9、块内偏移 1。10 个 token 使用 3 块共 12 槽，尾部空 2 槽；位置 12 需要新块。分页不改变每个 KV 数的精度，也不自动转移到 CPU。

### Q22 [P0] Continuous batching 是什么，为什么可能有用？

调度器按轮次管理活动请求：已有请求结束后，其他请求继续，新请求可在后续轮次加入，不必等待原批所有请求结束。它可以减少空闲机会并改善吞吐，但接纳受 KV、token 预算与序列数限制，较大并发也可能增加排队和单步延迟。与 KV 物理块管理是不同层次。

### Q23 [P0] Prefix caching 什么时候能复用，什么时候不能？

前缀 token 和所有影响该 KV 的上下文条件需要一致，包括模型及位置等。相同子串但前文不同不自动可复用；适配器、多模态输入等也可能影响缓存身份。vLLM 0.11.0 文档描述通过父块、本块 token 与额外信息建立块标识，并只缓存完整块；这是版本特定实现。命中主要减少重复 prefill，不代表 decode 不再读取上下文。[推理服务](inference-service.md)

### Q24 [P0] max_num_batched_tokens 与 max_num_seqs 分别限制什么？

前者控制一次调度/批处理的 token 预算，后者控制一批可调度序列数量；max_model_len 则约束支持的上下文长度。它们作用不同。调大 token 预算可能加快长 prefill，但也可能使 decode 间隔变差；应按版本和负载实测，不能当成固定单调关系。[vLLM 0.11.0 优化文档](https://docs.vllm.ai/en/v0.11.0/configuration/optimization.html)

### Q25 [P0] 显存不够、频繁 preemption 怎么办？

先看权重、KV 块、激活／工作区、CUDA Graph、其他进程及长度／并发分布，确认发生在启动、prefill 还是 decode。频繁抢占表明缓存或调度容量受压，可测试降低并发／长度、调整缓存预算或合理并行，并衡量重算开销与吞吐/时延。vLLM 0.11.0 的 V1 文档说明默认 preemption 模式为 recompute；不同版本需要确认。

### Q26 [P0] vLLM 高吞吐但用户觉得卡，怎么排查？

先统一指标，拆开请求排队、分词、prefill、KV 交接、decode 和网络输出，分别看 TTFT、ITL/TPOT 的 p95/p99 与错误率。统计单条时延和整体吞吐可能出现反方向变化；检查长 prompt 与短 decode 混合、连续批处理批量、缓存命中、preemption，定位后再调预算、资源和调度。

### Q27 [P1] speculative decoding 是什么？一定无损且一定更快吗？

草稿机制先提出多个 token，目标模型并行验证，接受一段可用前缀后再继续。贪心与随机采样有不同的接受/修正规则；在正确条件下可保持目标模型的输出或采样分布，但不保证每种近似实现都无损，也不保证相同随机种子逐 token 一致。低接受率、草稿成本高或高并发时可能变慢。[原论文](https://arxiv.org/abs/2211.17192)

### Q28 [P1] CUDA Graph 解决什么？和 FlashAttention 是一个东西吗？

CUDA Graph 在适用条件下捕获一组 GPU 操作并重放，减少 CPU/驱动反复提交 kernel 的开销；动态图形、内存地址与捕获资源可能造成约束。FlashAttention 是 attention 的分块计算及显存访问优化。两者作用层次不同，可按实现组合，但都不是性能必然改善的保证。

### Q29 [P0] 怎么设计一组可信的推理优化对照？

固定 GPU 数、硬件／模型版本、dtype、输入输出长度分布、到达率与采样配置，预热；测试长短 prompt、不同并发、前缀命中与否。报告 TTFT、ITL/TPOT 分位数、输入/输出吞吐、错误率、峰值显存及满足 SLO 的 goodput。一次只改关键因素，并检查质量、精度与性能；若比较分离部署，还应记录 KV 迁移带宽与两侧排队。

### Q30 [P0] 没有实际部署过 vLLM，被问项目经验怎么答？

先明确自己目前掌握的是原理与公开文档：能说明请求路径、调度、KV 分页和初步排障；如没有实际安装或部署，就不把命令阅读写成生产实践。再结合本人真实的 PyTorch 模型和性能分析经历，说明会怎样搭建最小实验并按延迟、显存、吞吐与正确性验证。具体项目事实以本人资料为准。

### Q32｜集合通信

**题目：** 四卡输入分别为 `[1,2,3,4]`、`[10,20,30,40]`、`[100,200,300,400]`、`[1000,2000,3000,4000]`。SUM AllReduce 与 ReduceScatter 的每卡输出是什么？若各卡的独立分片是 A/B/C/D，AllGather 输出是什么？

**参考答案：** 四个向量逐位置 SUM 为 `[1111,2222,3333,4444]`。AllReduce 后四卡均持有完整向量；ReduceScatter 后 rank0 到 rank3 分别持有 `[1111]`、`[2222]`、`[3333]`、`[4444]`。若输入是独立片 A/B/C/D，AllGather 后各卡为 `[A,B,C,D]`；没有做求和。

### Q33｜Ring 通信量与 ZeRO

**题目：** 四卡理想 Ring，完整逻辑张量 S=8 MiB，AllGather、ReduceScatter、AllReduce 各卡分别发送多少？若 AllGather 的题目改成“每卡输入 8 MiB”，又是多少？用这些操作解释 ZeRO-2／3 的基本思路。

**参考答案：** 完整逻辑大小 S=8 MiB，p=4，每片 2 MiB。AllGather 和 ReduceScatter 均 p−1=3 轮，每卡发送 `3×2=6 MiB`；AllReduce 两个阶段，每卡发 12 MiB。接收量相同，如果问题问发送加接收需要再乘 2。

若 AllGather **每卡输入**为 8 MiB，完整输出 S=32 MiB，每卡发 `3×8=24 MiB`。ZeRO-2 分片优化器状态和梯度，梯度可用 ReduceScatter 汇总至持有者；ZeRO-3 进一步分片参数，计算时还需 AllGather 所需参数。不同实现的预取、重分片策略影响总通信次数。[集合通信与分片](parallel-moe.md#collective)

### Q34｜Ring Attention

**题目：** 四卡按序列等分，rank0 的 Q 保留在哪里，K/V 依次如何到来？为什么不能对每块局部 softmax 的结果求平均？因果 mask 和通信计算重叠分别需要注意什么？

**参考答案：** 本地 Q 和输出累计量保留在原卡。对于 `0→1→2→3→0` 的环，rank0 依次计算 KV0、KV3、KV2、KV1；其他卡同步处理自己的 Q。每块更新全局 softmax 的最大值、指数和与加权和，最后再归一化。独立软最大后平均丢失块间的分母比例，因此不对。

因果 mask 依据 token 的全局位置；不可见整块可跳过计算，但要考虑后续其他 rank 是否仍依赖该块传递。计算与传输可以重叠，是否隐藏取决于块大小、网络、设备与调度；通信没有消失。[Ring Attention](parallel-moe.md#ring)

### Q35｜并行与 batch

**题目：** DP、TP、PP、EP、CP 分别切分什么？DP=4、TP=2、每个 DP 副本微批 3、梯度累积 2，全局 batch 多少？为什么不是乘以 8 张卡？

**参考答案：** DP：模型副本分样本、同步梯度；TP：分层内矩阵、拼接或归约；PP：分网络层、传激活和梯度；EP：分专家、分发与回收 token；CP：按序列位置分激活，需要跨段注意力通信。

独立数据副本是 DP=4，每副本 microbatch 3、累积 2，故全局 batch `4×3×2=24`。TP=2 的两张卡共同处理同一份数据，并非两份独立样本；要说明每卡局部 batch 与 DP 副本的语义。

### Q36｜MoE 前向

**题目：** 100 个 token、top-2、4 专家。说明路由、分组、发送、专家计算、回收与加权；理想每个专家处理多少个 assignment？为何稀疏激活不保证加速？

**参考答案：** router 对每个 token 选 top-2，得到路由及权重；按目标专家重排 token，跨卡时分发到持有专家的设备，各专家计算，结果返回后按权重累加到原 token。总 assignment 为 100×2=200，四专家理想平均各 50。

理论激活参数减少仍可能受专家 token 批量小、重排、跨卡 All-to-All、热点等待、显存与 kernel 启动限制。测整体延迟及各阶段，而不是只看 FLOPs。

### Q37｜负载

**题目：** 8 个 token、top-1、4 专家，分配 [6,1,1,0]。capacity factor=1.5，按 `ceil(c·Tk/E)` 算每专家容量。哪些 token 可能溢出？辅助 loss 如何让 router 收到梯度？padding、dropless 和专家副本分别处理什么？

**参考答案：** 容量 `ceil(1.5×8×1/4)=3`；E0 收到 6、超过 3 的是 3 个 assignment，如何选择被丢／绕过由实现确定。其他专家负载分别为 1、1、0。

一种均衡辅助项以硬分配比例 f 和完整 softmax 平均概率 P 构造 `E ΣfᵢPᵢ`。硬计数通常不参与梯度，但 P 通过 router 的 softmax 可微，对热点概率施加压力；均衡 loss 并非每次都保证均匀。padding 可能浪费计算，丢弃可能损失信息；dropless 避免丢失但仍面临不均和执行开销。推理时给热门专家部署同权重副本可分摊负载，需额外权重显存与调度，不等同于把 token 发给另一个不同专家。[MoE](parallel-moe.md#moe)

### Q38｜定位与计时

**题目：** 训练双卡比单卡慢，GPU 利用率低，或卡在 collective。怎样区分数据、计算、通信及某个 rank 提前退出？如何正确测量 CUDA 异步操作？

**参考答案：** 固定模型、全局 batch、数据及精度，先检查吞吐和每步时间，必要时按 rank 分别记录。看数据加载、主机预处理、H2D、前向反向、优化器、collective 的时间线和等待；比较单卡、同机双卡和跨机配置，避免把利用率单一数值当根因。发现 hang 时检查所有 rank 最早异常、通信组／顺序／shape／dtype；一张卡 OOM 退出，其他卡可能超时。

CUDA kernel 启动通常异步，CPU wall clock 直接包调用可能只测到提交。墙钟测试在测量前后同步设备，或用 CUDA events 并等待事件完成；预热并多次测量，明确是否包含数据拷贝、排队、同步及 profiler 开销。

### Q39｜路由整理代码

**题目：** 给定 `routes=[[1,0],[0,2],[1,2]]` 和 3 个专家，构建按专家分组的 `(token_idx,slot_idx)` 列表，并说明如何将专家输出按路由权重加回原 token；同一 token 的多个输出为什么要累加？若有余力扩展双向链表 LRU。

**参考答案：** ```python
def group_routes(routes, num_experts):
    groups = [[] for _ in range(num_experts)]
    for token_idx, selected in enumerate(routes):
        for slot_idx, expert_id in enumerate(selected):
            if not 0 <= expert_id < num_experts:
                raise ValueError('invalid expert')
            groups[expert_id].append((token_idx, slot_idx))
    return groups
```

示例返回 `[[ (0,1),(1,0) ], [ (0,0),(2,0) ], [ (1,1),(2,1) ]]`。时间 O(Tk+E)，输出保存 Tk 个 assignment。返回后用保存的 token/slot 索引取路由权重，对同一 token 的多个专家输出做加权**累加**；不能简单拼接，因为一个 token 可有多份专家结果。该示例没有跨设备通信和专家计算。[完整 MoE 前向](parallel-moe.md#k07)；[LRU 代码](engineering-data.md#k08)。

### Q40｜数据与反问

**题目：** attention mask 和 loss mask 有何区别？提出两个关于任务、设备或团队协作的问题。

**参考答案：** attention mask 决定 query 可以读取哪些 key；loss mask 决定哪些标签位置计入损失。比如用户提示 token 可以被后续回答看到，但训练时其标签可以不计入 loss。注意目标移位只做一次。

反问可选：团队当前工作主要集中在训练还是推理、实际设备与框架是什么；实习生前几周任务和验收方式怎样、与算法团队如何协作。以对方回复为准。

### Q41｜ICCV 项目

**题目：** 介绍 ICCV 的问题、三部分技术主线和一项有范围的实验结果。为什么要做标定与仿真？展开网络是什么，物理模型在每阶段起什么作用？如果真实数据提升不稳定，如何区分仿真失配和网络问题？

**参考答案：** **主线**：干涉高光谱观测含强且与仪器相关的复杂退化，又缺少配对训练数据。先按光学响应和电子噪声建立退化模型，再用真实标定数据估参数并生成配对训练数据，最后把数据一致性与 Transformer 图像先验结合到展开网络 IHRUT。真实 Calibration 三场景中，IHRUT-7 平均 39.61 dB，MAUN-7 为 38.15 dB，差 1.46 dB；这是该设置的 PSNR 比较。

**为什么标定与仿真**：每台仪器参数有差异，先估计具体退化再合成观测，才能得到与目标仪器更接近的监督样本。模型仍可能遗漏真实噪声，仿真数据不自动等于真实数据。

**展开网络**：把迭代优化的若干步对应为网络的多个阶段；每阶段先用成像模型比较当前估计与观测、作数据一致性修正，再用可训练 Transformer 恢复结构。进一步诊断时，可分别检查标定参数／仿真残差、真实和合成数据效果、固定数据改网络与固定网络改退化模型的消融，避免只凭一次成绩归因。以 [self](self.md) 中本人写法及论文为准。

### Q42｜缓存与非等长 mask

**题目：** 以 prompt A/B/C 后生成 D、E 为例，解释 prefill、decode 和缓存时点。历史长度 3、本次输入 2 时，给出两行因果 mask。为什么历史 Q 不必作为下一步缓存？

**参考答案：** Prefill 输入 A/B/C，计算各层 K/V 并用 C 位置 logits 采样 D；D 真正进入下一次前向时，才计算并追加 D 的 K/V，然后用它的输出采样 E。历史 Q 用于过去位置的输出；下一步只需新 Q 查询历史和本位置的 K/V，因此无需保存历史 Q 作为 KV cache。

历史位置 0、1、2，本次 query 绝对位置 3、4，对应 key 位置 0—4。True 为可见时两行为 `[1,1,1,1,0]`、`[1,1,1,1,1]`。真实批次可能还需 padding mask。不能默认任意接口对 Tq≠Tk 的 `is_causal` 都按这个右对齐语义处理，需检查接口定义。

### Q43｜量化

**题目：** 解释 W4A16、INT8 对称量化的 scale、PTQ/QAT。为什么权重缩小 4 倍不意味着端到端速度也提升 4 倍？权重量化会自动减少 KV 吗？

**参考答案：** W4A16 表示权重以 4 位量化形式存储，激活按该方案使用 16 位表示；不表示 KV 一定 4 位。对称 INT8 的例子取 `s=max(abs(x))/127`，`q=clip(round(x/s),-127,127)`，反量化 `x̂=sq`；全零组需单独处理 scale。

PTQ 在训练后量化，部分方法需要校准数据；QAT 在训练中模拟量化效应。权重理论存储下降不等于速度按比例上升：还有 scale/分组元数据、反量化、内核支持、激活／KV 读取、计算和通信。对比需测同精度基线、同输入、吞吐／延迟及任务质量。具体看 [量化](inference-service.md#quant)。

### Q44｜GQA 手写

**题目：** 给定已投影 Q `[B,Hq,Tq,d]`、K/V `[B,Hkv,Tk,d]` 和允许矩阵 `[Tq,Tk]`，实现 GQA 核心前向，保证 Hq 可被 Hkv 整除，返回 `[B,Hq,Tq,d]`。说明分组映射、softmax 轴和全屏蔽行。可先写单头注意力，再口述如何扩展为分组；不要求编写 CUDA kernel。

**参考答案：** 先检查 `Hq%Hkv==0`，设 g=Hq/Hkv；将 Q reshape 为 `[B,Hkv,g,Tq,d]`，K 扩维为 `[B,Hkv,1,Tk,d]`；矩阵乘得到 `[B,Hkv,g,Tq,Tk]` 的分数。按最后的 key 维 softmax，再乘 V 的 `[B,Hkv,1,Tk,d]`，合回 `[B,Hq,Tq,d]`。先按允许矩阵屏蔽不可见位置，全屏蔽行必须显式处理。

[GQA 完整教学实现](model-attention.md#gqa)不显式复制 KV；若用 repeat_interleave 也可作为正确性参照，但不要当性能方案。实际缓存时 mask 要用绝对位置，不能只看形状。
