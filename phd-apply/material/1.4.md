# SkillMCTS：从语言先验到自进化代码技能的无梯度决策框架

## 摘要

结构化马尔可夫决策过程（MDP）中，以 AlphaZero 为代表的深度强化学习方法依赖海量交互样本与端到端梯度训练。在无梯度、无预训练数据的冷启动场景下，快速适应此类任务仍是一个开放难题。人类丰富的自然语言策略知识（如棋谱、攻略）提供了重要的无梯度先验来源，但这些先验与实际决策之间存在语义鸿沟，其适用条件与有效性也难以系统验证。为此，本文提出 SkillMCTS 框架，核心思想是：受 Code-as-Policy 启发，利用大语言模型（LLM）将语言策略编译为模块化代码技能库，以混合专家（MoE）形式作为先验引导蒙特卡洛树搜索（MCTS），跨越语义鸿沟；同时利用 MCTS 搜索产生的后验分布反向评估技能质量，通过乘性权重（Multiplicative Weights）在线更新各技能的可信度，并在技能持续失效或覆盖不足时，以经验反例驱动 LLM 对技能库进行定向进化。在 Sokoban、五子棋和 2048 三个互补环境中的实验表明，SkillMCTS 实现了无梯度的在线自适应决策，并产出可执行、可解释的技能资产，可供智能体复用或供人类玩家分析和参考。

## 1. 引言

结构化 MDP 广泛存在于博弈、规划等复杂决策场景中。以 AlphaZero 为代表的深度强化学习方法，通过 MCTS 与深度神经网络的结合，在围棋等任务上取得了超人类成就。然而，这类方法的卓越性能依赖于海量交互样本与端到端的梯度训练。当面临全新环境，无法从零收集数据并重新训练网络时，如何在有限交互中快速适应？对于缺乏先验信息的现有方法而言，这种冷启动适应是一个核心难题。

人类面对新任务时的行为提供了重要启发：玩家通过查阅棋谱、阅读攻略，借助语言化的先验知识快速上手。自然语言先验不仅信息丰富、表征能力强，而且具备天然的决策透明性与可解释性。然而，将自然语言作为先验引入结构化 MDP 面临两大挑战。一是**语义鸿沟（Semantic Gap）**：语言策略难以直接转化为精确的状态-动作执行逻辑。尽管大语言模型（LLM）在文本任务中表现出色，但在结构化离散 MDP 中，LLM 难以仅凭语言能力精确建模环境策略，且决策 Token 和时间开销巨大、输出不稳定。二是**验证困境（Verification Dilemma）**：语言先验本身可能存在偏差或错误，适用范围受限。在有限交互经验下，现有方法难以对先验的可靠性进行系统性评估与迭代——往往只能盲目执行先验，无法判断其可靠性与适用范围，也无法进行总结反思。

针对语义鸿沟，近期 Code-as-Policy 研究提供了重要启发：与其让 LLM 直接输出动作，不如让其生成可执行代码作为决策的中间表示。据此，我们将自然语言先验"编译"为模块化、可执行的代码技能，在保留语言可解释性的同时，获得更精确、更高效的决策形式。针对验证困境，我们观察到 MCTS 本身蕴含天然的评估信号：搜索树中经充分模拟的节点，其后验访问分布随模拟次数增加而收敛于真实最优策略，与先验偏向无关（先验仅影响收敛速度）。这意味着先验技能不仅可引导探索，还可被搜索产生的后验分布"反向检验"——与后验一致的技能被证实，偏离者被证伪，无需外部基准或额外计算开销。

基于以上洞察，本文提出 **SkillMCTS** 框架，将 LLM 重新定位为"策略假设的编译器与进化引导者"，通过两个阶段构建从先验到自进化的闭环：

**编译（Compile）**：LLM 将语言策略编译为模块化代码技能库。每项技能以可执行代码 + 自然语言描述的形式存在，并在生成阶段主动聚类归并同质化策略。多技能按可信度加权，以混合专家 (MoE) 形式协同构成 MCTS 的搜索先验——各技能的贡献由其适用度 $m_k(s)$ 与归一化可信度权重的乘积调制，经全局均匀混合后归一化。

**验证与适应（Verify & Adapt）**：搜索完成后，系统遍历搜索树，收集高访问量节点的 MCTS 后验统计量纳入经验缓冲池（Buffer），以价值优势信号构造各技能的损失，通过乘性权重（Multiplicative Weights, MW）批量更新可信度 $\tau_k$。乘性更新天然具有"优者留存且增强、劣者衰减至静音"的特性，享有 $O(\sqrt{T \log K})$ 的次线性遗憾界。当技能持续失效或出现覆盖盲区时，触发**进化（Evolve）**机制——从 Buffer 提取诊断反例，驱动 LLM 定向修正或新增技能。

在 SkillMCTS 中，先验的亮点被验证并充分利用，缺陷得到修正和补足，在无梯度条件下实现自校正、自进化的能力。SkillMCTS 的最终产出不仅是无梯度决策智能体，更是一套可执行、可解释、可复用的技能资产——每项技能以可读代码和自然语言描述的形式存在，为智能体的决策过程提供透明审计的基础，甚至可直接作为"智能教练"向人类玩家输出情景化的策略建议。

**本文贡献**：

- **（1）代码化技能编译与后验验证闭环**：提出将语言先验编译为模块化代码技能库，以 MoE 协同决策；利用 MCTS 搜索后验分布作为验证信号，通过乘性权重批量更新形成"编译 → 验证 → 适应"闭环。

- **（2）价值优势驱动的乘性权重自进化机制**：以 MCTS 的 Q/V 估计构造价值优势损失，通过乘性权重批量更新技能可信度（快时间尺度），结合可信度驱动的技能进化（慢时间尺度），实现无梯度自进化。乘性更新等价于 Hedge 算法，具有 $O(\sqrt{T \log K})$ 遗憾界。

- **（3）多环境实验验证**：在 Sokoban（规划）、五子棋（对抗）和 2048（随机）三个互补环境中，通过四级先验质量分层、16 项系统性 baseline（含传统 MCTS 参考线、梯度学习方法、LLM 决策方法、功能组件消融与设计选择消融）和若干核心分析实验，全面验证了框架各组件的有效性。

## 2. 相关工作

本文工作横跨 LLM 决策、MCTS 先验学习、Code-as-Policy 三个领域，并与在线学习理论存在深层联系。

### 2.1 LLM 用于决策与规划

ReAct [Yao et al., 2023] 将推理与动作交织，通过思维链在文本环境中进行交互式决策。Tree of Thoughts [Yao et al., 2024] 将决策建模为树搜索，支持思维路径的回溯与评估。LATS [Zhou et al., 2024] 将 ToT 与 MCTS 结合，利用 LLM 生成和评估搜索节点。Reflexion [Shinn et al., 2023] 引入语言层面的自我反思机制改进后续行为。

上述方法的共同前提是状态空间为**文本描述或开放世界**，动作语义与 LLM 生成空间自然对齐。然而，在**结构化离散 MDP**（如棋盘、网格世界）中，状态由精确数值结构定义，动作须严格符合环境规则。这一差异导致 LLM-as-Policy 面临执行鸿沟（LLM 输出难以保证离散动作合法性）与语义鸿沟（语言策略与精确状态映射之间的损耗）。本文与上述方法的根本区别在于：**LLM 不作为实时决策者，而是编译器与进化引导者**——仅在初始化时编译技能库、进化时修正代码，运行时完全由 MCTS + 乘性权重更新驱动，LLM 零调用。

### 2.2 MCTS 与先验学习

AlphaZero [Silver et al., 2017] 通过神经网络提供策略先验与价值估计，经 PUCT 引导搜索，再以搜索结果训练网络，形成自我对弈循环。MuZero [Schrittwieser et al., 2020] 进一步学习了隐式环境模型。近期工作探索以 LLM 替代神经网络为 MCTS 注入先验：LLM-MCTS [Zhao et al., 2024] 每步搜索扩展时调用 LLM 生成动作分布；RAP [Hao et al., 2023] 利用 LLM 作为世界模型和奖励函数进行规划式推理。

这些工作的共同局限在于：（1）**高频 LLM 调用**——每步扩展都需调 LLM，难以用于实时决策；（2）**单向信息流**——MCTS 积累的丰富统计量在动作选择后被丢弃，未反向用于评估和改进先验。本文继承"先验引导搜索"的基本范式，但在两方面形成超越：（1）以预编译代码技能库替代实时调用，运行时 LLM 调用频率从 $O(T \cdot N_{\text{sims}})$ 降至 $O(1)$；（2）将 MCTS 后验统计量从被废弃的中间产物升级为技能验证的反馈信号，使"先验 → 搜索 → 后验 → 评估先验 → 更新先验"形成闭环。

### 2.3 Code-as-Policy 与可编程策略

Code-as-Policy [Liang et al., 2023] 将自然语言指令转化为可执行代码，在机器人控制中展示了代码策略的可行性。Voyager [Wang et al., 2023] 在 Minecraft 中利用 LLM 生成 JavaScript 代码技能，通过执行成功/失败的二元反馈迭代技能库。ProgPrompt [Singh et al., 2023] 以程序代码表达机器人任务规划。这些工作证实了代码作为策略表示的有效性，但与本文存在三个层面的本质区别。

**第一，技能定位与组合方式不同。** Voyager 等工作的技能是"底层执行器"——按匹配度择优调用。本文的技能是"决策专家"——通过单一函数 $f_k(s, \mathcal{A}_{\text{legal}})$ 同时完成状态解析与策略推荐。多技能以 MoE 协同：每个专家按其适用度与可信度的乘积贡献策略推荐，所有专家贡献经全局均匀混合后归一化。与乘积式专家（PoE）的合取语义（"所有专家必须同意"）不同，加性组合的析取语义（"任一专家推荐的动作都有机会"）更匹配技能互补（各管一摊）的设计哲学。当策略建议冲突时，MCTS 搜索自行仲裁，无需额外冲突消解模块。

**第二，验证信号的信息丰度不同。** CaP 和 Voyager 依赖二元或标量反馈，信息稀疏且滞后。本文以 MCTS 后验 $\hat{\pi}(a|s)$ 作为验证信号，是动作空间上的完整概率分布，信息量远高于二元标量，且每步 MCTS 完成后即时可得。

**第三，适应机制的自校正性质不同。** 已有方法的代码迭代遵循"生成→执行→评价→再生成"的开环模式。本文通过乘性权重可信度更新建立闭环——PUCT 探索确保搜索不被高可信度技能垄断，一旦发现更优动作则自动纠偏，适应过程具有理论可分析性（见附录 A）。

| 方法 | 技能表示 | 技能关系 | 验证机制 | 适应方式 | LLM 调用频率 |
|------|----------|----------|----------|----------|-------------|
| CaP | 完整程序策略 | 单一策略 | 任务完成度（标量） | 静态 | 低（仅初始化） |
| Voyager | 程序化行动序列 | 择优调用 | 执行成功/失败（二元） | 代码库迭代 | 高 |
| ProgPrompt | 程序化任务规划 | 层次调用 | 任务完成度 | 静态 | 低（仅初始化） |
| LLM-MCTS | LLM 实时输出 | 无持久技能 | 无显式验证 | 无适应 | 极高 |
| **SkillMCTS (本文)** | **模块化决策专家** | **MoE 协同** | **MCTS 后验分布（连续）** | **乘性权重批量更新 + 定向进化** | **低（初始化+进化）** |

### 2.4 在线学习与专家组合

本文的技能可信度更新在数学上属于在线专家建议问题。经典 Hedge 算法 [Freund & Schapire, 1997] 通过 multiplicative weights 在线调整权重，具有 $O(\sqrt{T \log K})$ 的对抗性遗憾界 [Hazan, 2016]。Hedge 的标准形式在概率单纯形上操作（$\sum_k w_k = 1$），权重只反映相对排序——当所有技能质量都很高（或都很低）时，仍需排出高低，无法独立判断单个技能是否"足够好"。

本文采用非归一化的乘性权重更新，基于两个考量。**（1）进化需要绝对质量判断**：技能进化需要回答"该技能是否应被修正？"——这是一个绝对判断。乘性权重在 log 空间中做加性累积，$\log \tau_k$ 直接追踪技能的累积负损失，为触发进化提供自然信号；而归一化权重只反映相对排名，无法独立判断一个技能是否"坏"。**（2）动态技能集兼容性**：非归一化设计使技能增删不影响其他技能的 $\tau_k$——新技能以 $\tau_k = 1$ 直接加入，淘汰技能直接移除，其余不受影响。标准 Hedge 每次增删均需调整权重单纯形。

值得说明的是，$\tau_k$ 的非归一化性质服务于**更新与进化**（需要绝对质量判断），而在**组合阶段**（MoE 先验生成）则对激活技能集内做归一化，以保证在不同激活数量下探索系数 $\lambda$ 的有效性一致。这一"分阶段归一化"的设计将可信度的积累与使用解耦，详见 §4.2.2。

## 3. 问题构建

### 3.1 问题形式化

考虑结构化 MDP $\mathcal{M} = (\mathcal{S}, \mathcal{A}, P, R, \gamma)$，可为单智能体环境或零和博弈。

**输入**：
- 环境规则的语言说明 $R(\mathcal{M})$
- 策略先验文本集 $P_{\text{text}} = \{p_1, \dots, p_m\}$，每条为纯自然语言策略规则（不含代码、伪代码或数学公式）
- LLM 接口 $L$

**约束（无梯度适应）**：
- 禁止在 $\mathcal{M}$ 上预先收集大规模交互轨迹
- 禁止在 $\mathcal{M}$ 上执行任何形式的梯度下降或神经网络参数更新
- 允许有限步数的在线交互
- 允许调用 LLM 进行代码生成、分析与文本理解

**输出**：可解释技能库 $\mathcal{H} = \{h_1, \dots, h_K\}$ 及决策策略 $\pi_{\mathcal{H}}: \mathcal{S} \to \Delta(\mathcal{A})$

**优化目标**：给定交互预算 $T$，最大化期望累积奖励 $\mathbb{E}\left[\sum_{t=1}^{T} \gamma^{t-1} R(s_t, a_t)\right]$，同时满足可解释性约束（每个技能以人类可理解的代码 + 自然语言描述形式存在）。

### 3.2 实验环境

选取三个互补环境，覆盖不同决策维度：

| 环境 | 类型 | 关键特征 | 验证维度 |
|------|------|---------|---------|
| **Sokoban** | 单智能体、确定性 | 长程规划、状态组合爆炸 | 规划能力与技能组合 |
| **五子棋** | 双智能体、对抗性 | 局部模式识别、攻防权衡 | 对抗策略与模式匹配 |
| **2048** | 单智能体、随机性 | 启发式评估、随机转移 | 随机环境下的启发式适应 |

## 4. 方法

### 4.1 总体框架与预处理

SkillMCTS 框架按两条逻辑线组织为两个阶段：

> **阶段一（编译）**：语言先验 → 代码技能 → MoE 引导 MCTS 搜索
> **阶段二（验证与适应）**：MCTS 搜索树后验 → Buffer 批量乘性权重更新 → 可信度驱动进化 → 更优技能 → ...

阶段一中 LLM 扮演"编译器"角色，将语言策略转化为模块化代码技能，并通过 MoE 组合注入 MCTS 搜索。阶段二中 LLM 仅在技能进化触发时作为"修改者"介入；运行时完全由 MCTS + Buffer 批量乘性权重更新驱动，确保计算效率与执行精确性。

**预处理：世界模型构建**。LLM 根据环境规则 $R(\mathcal{M})$ 生成可执行模拟器 $\mathcal{M}_0$，提供 `step()`、`legal_actions()`、`is_terminal()` 等标准接口，作为 MCTS 的搜索环境。生成后通过随机轨迹的边界测试自动验证并修正（最多 3 轮）。对比实验优先使用经过验证的开源环境实现；LLM 生成版本仅用于消融评估全自动场景的鲁棒性（§5.6.3）。

### 4.2 阶段一：编译 —— 从语言先验到代码技能引导的搜索

阶段一完成两项任务：（1）将语言先验编译为模块化代码技能库；（2）以 MoE 形式将技能组合为先验注入 MCTS 搜索。

#### 4.2.1 技能组件与编译流程

技能库 $\mathcal{H} = \{h_1, \ldots, h_K\}$ 中的每个技能是一个自包含的决策专家，包含以下组件：

- **决策函数** $f_k(s, \mathcal{A}_{\text{legal}}) \to (m_k(s), \pi_k)$：接收当前状态与合法动作集，输出适用度 $m_k(s) \in [0,1]$ 和动作推荐概率分布 $\pi_k \in \Delta(|\mathcal{A}_{\text{legal}}|)$。该函数将状态解析与策略推荐合并为单一逻辑单元，消除跨函数特征对齐的额外错误源。
- **可信度** $\tau_k \in [\tau_{\min}, \tau_{\max}]$：该技能经 MCTS 后验反复验证为可靠的程度。由预处理过程差异化初始化——保留档 $\tau_k^{(0)} = 1.5$，修正档 $\tau_k^{(0)} = 0.5$，LLM 补充的新技能由模型自行评估。在线交互中通过乘性权重更新（§4.3.1）持续调整。$\tau_k$ 在 log 空间中累积负价值优势：$\log \tau_k$ 实质上是技能决策质量的指数加权和。$\tau_k \gg 1$ 表示技能推荐的动作持续优于后验平均；$\tau_k \to 0$ 表示技能推荐持续劣于后验平均。设置上界 $\tau_{\max} = 5.0$ 防止单一技能过度集中，下界 $\tau_{\min} = 10^{-3}$ 防止数值下溢。
- **自然语言描述** $d_k$：说明适用场景与策略含义，用于人类审计。

所有技能以 Python 代码存在（单技能约 30–60 行），完整接口规范见附录 C。

**编译流程**。给定策略先验文本集 $P_{\text{text}}$ 和环境规则 $R(\mathcal{M})$，LLM 分两步将语言先验编译为代码技能：

1. **语言先验预处理**：考虑到先验质量对技能生成和整个算法的影响重大，我们令LLM对语言先验做一系列的预处理，分为以下几个步骤。
**语义聚类**：LLM先分析和理解语言先验，先对语义高度相似或描述同一决策模式的条目在此阶段被主动归并（如"堵截活三"与"防守活三"）。
**评估**：LLM 对 $P_{\text{text}}$ 中的每条先验评估质量与合理性，给出初始的 $\tau$ 值。评分结果分三档处置：（a）保留——直接进入后续流程；（b）修正——LLM 给出修改后的描述文本，以修正后的形式保留；（c）丢弃——与 $R(\mathcal{M})$ 明显矛盾、完全不适用的条目直接移除。
**补充**：处理完毕后，若剩余条目不足 $K$，LLM 基于 $R(\mathcal{M})$ 和自身的知识自主生成合理的策略补充条目以补齐至恰好 $K$ 条；若超出则按评分裁减。
最终，输出 $K$ 条附带差异化初始可信度的语言策略描述。

2. **代码生成和一致性检验**：将预处理后的 $K$ 条语言策略逐条翻译为可执行的决策函数 $f_k(s, \mathcal{A}_{\text{legal}})$ 代码。每个技能以 `skill_<name>` 为函数名，接收当前状态与合法动作列表，返回适用度与动作推荐概率分布。生成后在 $\mathcal{M}_0$ 上做基础可执行性验证（语法、输出类型与合法性），失败触发修正（最多 3 轮）。策略质量的完整验证留待在线阶段（§4.3）通过 MCTS 后验完成。

#### 4.2.2 MoE 先验组合与 MCTS 搜索

在状态 $s$ 下，对每个技能调用其决策函数 $f_k(s, \mathcal{A}_{\text{legal}})$ 得到适用度 $m_k(s)$ 和推荐分布 $\pi_k$，识别激活技能集 $\mathcal{A}(s) = \{k : m_k(s) > \delta\}$（$\delta = 0.1$ 为激活阈值）。若 $\mathcal{A}(s) = \emptyset$，回退为均匀先验。

**MoE 先验**。首先在激活技能集内对 $\tau_k$ 做归一化，得到各技能的组合权重：

$$w_k(s) = \frac{m_k(s) \cdot \tau_k}{\sum_{j \in \mathcal{A}(s)} m_j(s) \cdot \tau_j} \tag{1}$$

然后按加性形式组合各技能的策略推荐，并混合均匀分布作为探索下界：

$$\pi_{\mathcal{H}}(a|s) = (1-\lambda) \cdot \sum_{k \in \mathcal{A}(s)} w_k(s) \cdot \pi_k(a) + \lambda \cdot \frac{1}{|\mathcal{A}_{\text{legal}}|} \tag{2}$$

其中 $\lambda = 0.02$（Sokoban/五子棋）或 0.03（2048）。归一化权重 $w_k(s)$ 确保无论激活技能数量和 $\tau_k$ 取值如何，$\lambda$ 的有效探索率保持一致。最后归一化：

$$\tilde{\pi}_{\mathcal{H}}(a|s) = \frac{\pi_{\mathcal{H}}(a|s)}{\sum_{a'} \pi_{\mathcal{H}}(a'|s)} \tag{3}$$

**设计说明**：式 (1) 中的归一化将可信度的"积累"（更新阶段，$\tau_k$ 独立演化）与"使用"（组合阶段，$w_k$ 归一化）解耦。非归一化 $\tau_k$ 服务于 §4.3.2 的进化触发（需要绝对质量判断），而归一化 $w_k$ 服务于先验组合的稳定性（$\lambda$ 在任何激活模式下均提供一致的探索下界）。在单技能激活的退化情况下，$w_k = 1$，技能以其原始策略 $\pi_k$ 贡献先验。

将组合先验 $\tilde{\pi}_{\mathcal{H}}$ 注入 PUCT 公式展开搜索：

$$a^* = \arg\max_a \left[Q(s,a) + c_{\text{puct}} \cdot \tilde{\pi}_{\mathcal{H}}(a|s) \cdot \frac{\sqrt{N(s)}}{1+N(s,a)}\right] \tag{4}$$

搜索完成后选择根节点访问次数最多的动作执行：$a_t = \arg\max_a N(s_t, a)$。

博弈环境（五子棋）中对手节点对价值取反（Negamax），按 minimax 原则搜索。随机环境（2048）中引入机会节点：动作后对空位采样 $K_{\text{chance}} = 8$ 个瓷砖生成位置，按 2（概率 90%）和 4（概率 10%）加权计算期望价值，机会节点深度限制为 6。所有 LLM 生成的技能代码在沙盒子进程中执行（5 秒超时 + 内存限制），违反时回退为均匀先验。

### 4.3 阶段二：验证与适应 —— 后验驱动的乘性权重更新与技能进化

阶段二利用 MCTS 搜索产生的后验统计量，同时完成两项任务：在线批量更新技能可信度（快时间尺度），以及在技能持续低可信或覆盖不足时触发定向进化（慢时间尺度）。两项任务通过经验缓冲池 $\mathcal{B}$ 共享数据。

**搜索树节点收集**。MCTS 搜索过程中，搜索树的非叶节点累积访问统计量 $N(s)$ 和后验分布 $\hat{\pi}(a|s) = N(s,a)/N(s)$。搜索完成后，遍历搜索树，将满足 $N(s) \ge \tau_N = 0.2 \cdot N_{\text{sims}}$ 且非终止的节点直接推入全局经验缓冲池 $\mathcal{B}$（LRU 策略，容量 $C_{\mathcal{B}}$）。每条经验记录：状态 $s$、合法动作集、后验访问分布 $\hat{\pi}(a|s)$、动作价值估计 $\hat{Q}(s,a)$、后验加权状态价值 $\hat{V}(s) = \sum_a \hat{\pi}(a|s) \cdot \hat{Q}(s,a)$，以及各激活技能的推荐分布。LRU 策略下新节点插入队首，重复节点自动去重并移至队首，满容量时淘汰最少使用的条目。收集多深度节点（而不仅是根节点）能充分利用搜索树各层的后验信息，提升数据利用效率。

#### 4.3.1 后验验证与批量乘性权重更新

**专家损失：价值优势**。技能 $k$ 在状态 $s$ 下的损失定义为该技能推荐动作的期望 Q 值与后验加权状态价值之差。在搜索树节点收集阶段，已对每个激活技能调用 $f_k(s, \mathcal{A}_{\text{legal}})$ 得到推荐分布 $\pi_k$，损失计算直接使用该分布：

$$\ell_k(s) = \hat{V}(s) - \sum_{a \in \mathcal{A}_{\text{legal}}} \pi_k(a) \cdot \hat{Q}(s,a) \tag{5}$$

其中 $\hat{Q}(s,a)$ 和 $\hat{V}(s) = \sum_a \hat{\pi}(a|s) \cdot \hat{Q}(s,a)$ 为该搜索树节点的动作价值估计与后验加权状态价值。价值优势损失直接度量技能推荐相对于 MCTS 后验的决策质量——技能推荐了多好的动作，而非其分布形状是否匹配后验：

- **$\ell_k < 0$**：技能推荐的期望 Q 值高于后验加权平均（优势为正），即技能推荐的动作优于后验的平均水平。乘性更新将**提升** $\tau_k$。
- **$\ell_k \approx 0$**：技能推荐与后验平均质量相当。$\tau_k$ 基本不变。
- **$\ell_k > 0$**：技能推荐的期望 Q 值低于后验加权平均（优势为负），即技能推荐的动作劣于后验平均水平。乘性更新将**衰减** $\tau_k$。

在有界奖励的 MDP 中，$\hat{Q}, \hat{V}$ 有界，因此 $\ell_k$ 有界，满足 Hedge 遗憾界的前提条件（附录 A.1）。价值优势 vs 交叉熵损失的对比讨论见附录 D.1。

**适用度加权的批量损失**。乘性权重更新以 mini-batch 为单位进行批量估计。对每个技能 $k$，仅在其声称适用的状态（$m_k(s) > \delta$）上评估损失——专家只应在自己擅长的领域接受检验。Batch 中技能 $k$ 的平均损失为：

$$\bar{\ell}_k^{(t)} = \frac{1}{|\mathcal{B}_{\text{batch}}^{(t)}|} \sum_{s \in \mathcal{B}_{\text{batch}}^{(t)}} m_k(s) \cdot \ell_k(s) \tag{6}$$

其中 $m_k(s)$ 作为加权因子：技能对某状态的适用度越高，该状态对其损失评估的贡献越大。当 batch 中技能 $k$ 在所有状态上的 $m_k(s) \le \delta$（即该技能在此 batch 中未被激活），该技能本轮不更新。

**乘性权重更新**。可信度通过乘性规则更新，并裁剪到 $[\tau_{\min}, \tau_{\max}]$：

$$\tau_k^{(t+1)} = \operatorname{clip}_{[\tau_{\min}, \tau_{\max}]}\left(\tau_k^{(t)} \cdot \exp\left(-\eta \cdot \bar{\ell}_k^{(t)}\right)\right) \tag{7}$$

其中 $\eta = 0.05$ 为学习率，$\tau_{\min} = 10^{-3}$ 防数值下溢，$\tau_{\max} = 5.0$ 防止单一技能可信度过度增长导致先验集中。

**更新语义**。式 (7) 的核心语义是"优者留存且增强、劣者衰减至静音"。在 log 空间中，更新等价于加性累积：

$$\log \tau_k^{(t+1)} = \operatorname{clip}_{[\log \tau_{\min}, \log \tau_{\max}]}\left(\log \tau_k^{(0)} - \eta \sum_{i=1}^{t} \bar{\ell}_k^{(i)}\right)$$

$\log \tau_k$ 实质上是技能 $k$ 的累积负价值优势。由于 $\ell_k$ 可正可负，$\tau_k$ 既可超越初始值 1.0（好技能的优势为负 → 负损失为正 → $\tau_k > 1$），也可衰减至接近 0（坏技能的优势为正 → 负损失为负 → $\tau_k < 1$）。$\tau_{\max}$ 上界确保即使是最优技能也不会无限膨胀其话语权——这为后进技能和新技能保留了一定的竞争空间。

**与 Hedge 的关系**。式 (7) 在指数梯度形式下等价于 Hedge 算法，区别在于额外引入了 $\tau_{\max}$ 上界裁剪。若将 $\tau_k$ 归一化为概率单纯形上的权重 $w_k = \tau_k / \sum_j \tau_j$，则 $w_k$ 的更新为标准 Hedge。保留非归一化 $\tau_k$ 的原因有二：（1）进化需要绝对质量判断——$\tau_k$ 的绝对值直接指示技能是否应被修正，无需参考其他技能；（2）技能增删时无需重归一化。§4.2.2 中组合阶段的归一化确保了先验混合的稳定性。

**经验缓冲池与批量更新**。维护全局 LRU 缓冲池 $\mathcal{B}$（容量 $C_{\mathcal{B}} = 100$），存储各状态下的后验分布、Q/V 估计与技能输出。满足 $N(s) \ge \tau_N$ 的节点直接推入 $\mathcal{B}$：LRU 策略下新节点插入队首，重复节点自动去重，满容量时淘汰最少使用的条目。每步从 $\mathcal{B}$ 中均匀采样 mini-batch $\mathcal{B}_{\text{batch}}$（$|\mathcal{B}_{\text{batch}}| = \min(20, |\mathcal{B}|)$），按式 (6)–(7) 执行批量乘性权重更新。冷启动阶段（$|\mathcal{B}| < 20$）使用全 Buffer；$|\mathcal{B}| = 0$ 时跳过更新。

**自校正性质**。一个核心关切是确认偏误——$\tau_k$ 影响先验，先验影响搜索，搜索又决定用于更新 $\tau_k$ 的后验，是否形成恶性循环？**结论是否定的**。PUCT 公式 (4) 中，先验项系数随动作访问量增长而单调衰减，而 $Q(s,a)$ 的影响力单调递增。因此即使某技能因暂时高可信度主导了早期搜索，若其推荐动作实际是次优的，MCTS 的探索机制（$\lambda$ 和 $c_{\text{puct}}$）确保其他动作获得初始访问，后验 $\hat{\pi}$ 向更优动作偏移 → $\ell_k \uparrow$ → $\tau_k \downarrow$ → 自校正完成。乘性更新下 $\tau_k$ 的衰减幅度 $\Delta\tau_k = \tau_k \cdot (e^{-\eta\bar{\ell}_k} - 1)$ 与当前 $\tau_k$ 成正比，大 $\tau_k$ 时自校正步幅更大。需指出的是，当模拟预算 $N_{\text{sims}}$ 显著不足时（如 $N_{\text{sims}} \ll$ 理论自校正界），自校正的速度和可靠性将受限，详见分析实验 §5.6 和附录 A.2。

#### 4.3.2 技能进化

可信度更新在固定技能集合内调整各专家的话语权，但无法修正技能内部逻辑的系统性偏差，也无法应对覆盖盲区。技能进化在慢时间尺度上解决这两个问题：技能修正针对技能本身的逻辑缺陷，技能新增针对技能库的表达盲区。

**触发条件**。每 $T_{\text{evo}}$ 步检查一次进化条件。一次进化完成后进入冷却期 $T_{\text{cool}}$，期间不触发新的进化。两种触发条件独立评估：

- **技能修正触发**：$\exists k: \tau_k < \theta_{\text{low}} \;\land\; N_k^{\text{act}} \ge N_{\min}$。其中 $\theta_{\text{low}} = 0.2$，$N_{\min} = 15$ 为自上次进化以来该技能的累计激活次数。
- **覆盖盲区触发**：$|\{s \in \mathcal{B} : \max_k m_k(s) < \delta\}| / |\mathcal{B}| > \rho_{\text{gap}}$，其中 $\rho_{\text{gap}} = 0.15$。新增仅在无待修正技能时触发。

**技能修正：反例驱动调优**。对每个触发技能 $h_k$：

1. **诊断反例提取**：从 $\mathcal{B}$ 中选取 $h_k$ 激活且损失最高的 $N_{\text{case}} = 5$ 个状态作为反例。每个反例包含：状态可视化、$h_k$ 推荐动作分布、MCTS 后验偏好动作分布、价值优势损失值。
2. **LLM 诊断与修正**：将反例提交 LLM，要求（a）逐反例分析分歧原因——条件判断误判还是策略打分有偏；（b）归纳共性失效模式；（c）在保持接口不变的前提下输出修正后的 $(f_k, d_k)$ 代码。最多两次修正尝试，均失败则保留原版并标记。

**技能新增：盲区驱动扩展**。从 $\mathcal{B}$ 筛选盲区状态集 $\mathcal{S}_{\text{gap}}$，选取其中覆盖最薄弱的 $N_{\text{sample}} = 5$ 个状态，提交 LLM 分析共同决策挑战并设计新技能。

**容量管理**。若 $|\mathcal{H}|$ 已达 $K_{\max}$，淘汰 $\tau_k \cdot N_k^{\text{act}}$ 最小的技能。

**影子评估与后处理**。任何进化操作生效前，在 $\mathcal{B}$ 上评估被修改/新增技能的损失：修正操作要求新技能在 $\mathcal{B}$ 上的平均损失严格低于旧技能；新增操作要求新技能的平均损失低于均匀分布的损失（$\bar{\ell} = 0$，即新技能具备正的价值优势）。不满足则回滚。通过后：被修改/新增技能的可信度重置为 $\tau_k = 1.0$，记录时间戳，重置冷却期。

### 4.4 算法总览与复杂度

```
Algorithm: SkillMCTS
Input: 环境规则 R(M), 策略先验 P_text, LLM, 交互步数 T
Output: 技能库 H = {h_k = (f_k, τ_k, d_k)}

// 预处理
1   M_0 ← BuildWorldModel(R(M))
// 阶段1: 编译
2   H ← GenerateSkills(P_text, M_0)    // 解析+预评估+代码生成+一致性检验
3   τ_k ← PreAssessedInit(H)           // 预评估差异化（保留 1.5/修正 0.5）
4   B ← ∅, t_last_evo ← -T_cool

// 阶段2: 验证与适应
5   for t = 1..T:
6       s ← ObserveState()
7       for each skill h_k in H:
8           (m_k, π_k) ← h_k.fn(s, A_legal)       // 单函数调用：适用度+推荐分布
9       A(s) ← {k: m_k(s) > δ}
10      if A(s) ≠ ∅:
11          w_k ← (m_k·τ_k) / Σ_j (m_j·τ_j)  for k∈A(s)    // 式(1), 激活集内归一化
12          π̃_H ← AdditiveMoE({π_k}, w)                   // 式(2)(3)
13      else:
14          π̃_H ← Uniform
15      // MCTS 搜索
16      for sim = 1..N_sims:
17          TreePolicy(s, π̃_H)            // PUCT, 式(4)
18      a ← argmax_a N(s, a)
19      Execute(a), observe r, s'
20      // 收集搜索树节点后验
21      for each node s' in SearchTree:
22          if N(s') ≥ τ_N and not IsTerminal(s'):
23              Compute π̂(s'), Q̂(s',·), V̂(s'), {π_k} for k∈A(s')
24              B.Push(s', π̂, Q̂, V̂, A_legal, {m_k, π_k})   // LRU, 重复去重
25      // 批量乘性权重更新
26      if |B| > 0:
27          B_batch ← UniformSample(B, min(20, |B|))
28          for k = 1..K:
29              ℓ̄_k ← (1/|B_batch|) · Σ_{s∈B_batch} m_k(s) · (V̂(s) - Σ_a π_k(a)·Q̂(s,a))  // 式(5)(6)
30              if m_k(s) > δ for some s in B_batch:
31                  τ_k ← clip(τ_k · exp(−η · ℓ̄_k), τ_min, τ_max)                       // 式(7)
32      // 技能进化（低频）
33      if t mod T_evo == 0 and t - t_last_evo ≥ T_cool:
34          if LowTrust(H, τ) or CoverageGap(H, B):        // 式触发条件
35              H_old ← Copy(H)
36              if LowTrust:   RefineSkills(H, B, LLM)
37              if CoverageGap: AddSkill(H, B, LLM)
38              if ShadowEval(H_modified, B) passes:       // 评估被修改技能
39                  ResetModifiedTrust(H)                  // τ ← 1.0
40                  t_last_evo ← t
41              else: H ← H_old
```

**复杂度**：单步 MCTS 为 $O(N_{\text{sims}} \cdot D \cdot |\bar{\mathcal{A}}| \cdot |\mathcal{A}|)$，$|\bar{\mathcal{A}}|$ 为平均激活技能数（稀疏激活下 $\ll K$）。搜索树遍历收集节点为 $O(\text{tree\_size})$，tree_size 受 $N_{\text{sims}} \cdot D$ 约束。Batch 更新 $O(|\mathcal{B}_{\text{batch}}| \cdot K \cdot |\mathcal{A}|)$（$|\mathcal{B}_{\text{batch}}| = 20$）。技能进化每 50 步最多一次，主要开销为影子评估 $O(|\mathcal{B}| \cdot |\mathcal{A}|)$（仅评估变动技能）。LLM 调用频率为 $O(1/T_{\text{evo}})$，远低于每步调用方案（$O(T \cdot N_{\text{sims}})$）。

### 4.5 理论性质（概要）

完整证明见附录 A。

**性质 1（乘性更新的遗憾界）**。乘性权重更新（式 7）等价于带裁剪的指数梯度下降。由于价值优势损失在有限奖励 MDP 中有界，$\tau_{\max}$ 裁剪仅引入常数因子，不影响渐近遗憾界。由 Hedge 标准结论，$T$ 轮累积遗憾为 $O(\sqrt{T \log K})$（附录 A.1）。

**性质 2（价值优势损失的决策导向区分性）**。价值优势损失直接度量技能推荐的决策质量而非分布匹配程度。设技能 A 在最优动作上分配全部概率（$\pi_k^A(a^*) = 1$），技能 B 在所有动作上均匀分配。即使技能 B 的分布形状更接近 $\hat{\pi}$，只要 $Q(s,a^*) \gg \hat{V}(s)$，技能 A 的损失将远低于技能 B。这一特性使价值优势损失天然偏好决策质量高的技能，与 SkillMCTS 的最终目标（最大化累积奖励）直接对齐。

**性质 3（自校正的渐近保证与有限样本条件）**。PUCT 标准结论保证 $N_{\text{sims}} \to \infty$ 时 $\hat{\pi}$ 收敛到真实最优分布，与先验 $\pi_{\mathcal{H}}$ 无关。在有限样本下：设技能推荐的次优动作 $a_k$ 与最优动作 $a^*$ 的 $Q$ 值差距为 $\Delta > 0$，则当

$$N_{\text{sims}} > \frac{4c_{\text{puct}}^2 \cdot |\mathcal{A}|}{\lambda \cdot \Delta^2} \cdot \log\frac{2}{\delta}$$

时，以概率至少 $1-\delta$，后验偏好 $a^*$ 超过 $a_k$，触发 $\tau_k$ 自校正。代入实验参数：Sokoban 下界约 1,600（与实验 $N_{\text{sims}}=100$ 存在 gap）；五子棋下界约 63,000（远超实验 $N_{\text{sims}}=1,000$）。需指出此 bound 基于最坏情况假设（技能将全部概率集中在次优动作上），且 PUCT 探索 + $\lambda$ 混合的实际效果远优于孤立分析。实验中通过扫描 $N_{\text{sims}}$ 系统检验自校正的实际效率（分析实验 §5.6.1.2）。

## 5. 实验设计

本节在三个互补环境中系统验证 SkillMCTS 各组件的有效性，围绕六个核心问题：（1）技能编译 + MoE + 乘性权重更新 + 进化的整体价值；（2）先验质量与预处理对各方法的鲁棒性影响；（3）$N_{\text{sims}}$ 对 MCTS 类方法性能的影响及技能先验在低模拟预算下的增益；（4）自校正性质在有限模拟预算下的实际表现；（5）设计选择（乘性权重 vs EMA、价值优势 vs 交叉熵、归一化 vs 非归一化组合）；（6）可解释技能资产的产出质量。实验分为**对比实验**（§5.5）和**分析实验**（§5.6），前者回答"方法是否有效"，后者回答"为什么有效、在什么条件下有效"。

实验采用与 RL/DL 训练范式一致的 **epoch 学习-验证循环**：每个 epoch 包含固定 episode 的 learn 阶段（在线适应）和 test 阶段（冻结评估），以学习曲线量化适应效率，支持与基于梯度的方法进行公平的样本效率比较。

### 5.1 实验环境

| 环境 | 状态/动作空间 | 任务目标 | 实验规模 |
|------|-------------|---------|---------|
| Sokoban | $8\times8$ 网格，4 方向移动 | 将所有箱子推至目标 | 100 关卡，每关 ≤100 步 |
| 五子棋 | $15\times15$ 棋盘，落子坐标 | 五子连珠获胜 | 200 局 |
| 2048 | $4\times4$ 网格，4 方向滑动 | 获得尽可能高的分数 | 100 局 |

**Sokoban 关卡来源**：Microban（40 关，easy）+ Aymeric（60 关，easy–medium），按难度均匀采样 100 关。为拓展性能差距空间，额外引入 Aymeric hard 关卡集（3–4 箱子）作为难度压力测试。Learn 和 test 阶段使用不相交的关卡划分（learn 80 关 / test 20 关，按难度分层采样）。

### 5.2 通用实验设置

#### 5.2.1 Epoch 学习-验证循环

沿用 RL/DL 的标准评估范式，所有方法（适用者）按 epoch 进行学习-验证大循环。每个 epoch 包含：

- **Learn 阶段**：$N_{\text{learn}}$ episode 的在线交互，使用 learn 模式。SkillMCTS 及其消融变体在此阶段允许更新技能可信度 $\tau_k$、触发进化、更新经验缓冲池 $\mathcal{B}$。无学习更新的 MCTS 基线（B2）在此阶段正常执行搜索，但不涉及任何学习更新。
- **Test 阶段**：$N_{\text{test}}$ episode 的固定测试集/固定对手交互，使用 test 模式。**完全冻结**：不更新 $\tau_k$，不触发进化，不修改技能库，不写入 $\mathcal{B}$。仅执行 MCTS 搜索并记录决策结果。

循环持续至达到最大 epoch 数 $E_{\max}$ 或满足收敛判定。默认配置：

| 参数 | Sokoban | 五子棋 | 2048 |
|------|---------|--------|------|
| $N_{\text{learn}}$（每 epoch） | 200 | 200 | 200 |
| $N_{\text{test}}$（每 epoch） | 100 | 100 | 100 |
| $E_{\max}$ | 25 | 25 | 25 |
| $E_{\text{conv}}$（收敛判定） | 3 | 3 | 3 |

**设计理由**：（1）Learn 阶段体现算法的在线适应能力——$\tau_k$ 更新、Buffer 积累、技能进化均在此阶段发生；（2）Test 阶段使用固定测试关卡集/固定对手，提供无偏泛化估计，避免 learn 阶段的在线适应与泛化评估混淆；（3）每个 epoch 的 test 指标连成学习曲线，横轴可切换为累积 learn episode 数，与 RL 的"每 $N$ episode 评估"范式公平对标；（4）五子棋 test 阶段使用固定对手（Equal-MCTS，$N_{\text{sims}} = 1000$，Uniform 先验），Sokoban/2048 使用固定测试关卡集（与 learn 关卡集不重叠，按难度分层采样）。

**收敛判定**：连续 $E_{\text{conv}} = 3$ 个 epoch 的 test 主指标变化幅度 < 2% 且无明显上升趋势时，视为算法收敛。若在 $E_{\max} = 25$ 内未收敛，报告 $E_{\max}$ 处的最终性能并注明未收敛。

**learn/test 分离的具体措施**：
- `mode=learn`：SkillMCTSAgent 执行 Buffer 收集（§4.3）、批量乘性权重更新（§4.3.1）、进化检查（§4.3.2）。MCTS 搜索过程中的 $\tau_k$ 按当前值参与先验组合。
- `mode=test`：SkillMCTSAgent 在 `update()` 中跳过所有权重更新和 Buffer 写入，进化检查强制跳过。MCTS 搜索使用冻结的 $\tau_k$ 和技能库。LLM 接口在 test 模式下完全禁用（无需 API key）。
- Checkpoint 在 learn 阶段结束时保存，test 阶段从同一 checkpoint 加载后冻结运行，确保 learn 和 test 使用完全相同的技能库状态。

#### 5.2.2 先验质量与预处理条件

先验质量与预处理条件的组合是**本研究的核心分析维度之一**。对于所有依赖技能先验的方法（B9–B12 及 SkillMCTS），均需在四级先验 × 预处理开关的完整矩阵上评估，以分离预处理（先验质量筛选与差异化 $\tau_k$ 初始化）和在线适应（权重更新 + 进化）的独立贡献。详细设计见 §5.6.1.1。

实验采用四级先验质量 × 预处理开关的矩阵设计。预处理（阶段 1，§4.2.1）开启时，LLM 在编译前对语言先验进行评估、合并与补齐，输出恰好 $K$ 条经过质量评分的先验条目，各技能按评分获得差异化的初始 $\tau_k$；关闭时，先验文件中的条目原样进入代码生成（§4.2.1 步骤 2），$\tau_k^{(0)}$ 统一为 1.0。两阶段的严格分离使预处理本身的价值可被独立消融。

| 等级 | 描述 | 文件条目数 | 来源 |
|------|------|-----------|------|
| **None** | 无先验（空技能库 → Uniform-MCTS） | 0 | — |
| **Misleading** | ≥10 条中 ≥60% 为故意误导 | ≥10 | LLM 生成 + 人工注入反例 |
| **Weak** | ≥10 条模糊/通用/无信息建议 | ≥10 | LLM 生成（弱 prompt） |
| **Standard** | ≥10 条合理策略建议 | ≥10 | LLM 生成（标准 prompt，**对比实验缺省**） |

**核心原则**：先验在实验运行前由固定 prompt 的 LLM 一次性生成，全文公开，不做人工筛选或修改。所有先验为纯自然语言（不含代码或数学公式）。生成先验的 LLM 与 SkillMCTS 内部使用的 LLM 分离（独立的 system prompt）。每条先验文件至少包含 10 个条目，确保无预处理条件下（B9、B11）的技能数量与有预处理条件可比。

### 5.3 评价指标

#### 5.3.1 性能指标

| 环境 | 主指标 | 辅助指标 |
|------|--------|---------|
| Sokoban | 解决率（Solve Rate） | 平均步数、死局率 |
| 五子棋 | 对 Equal-MCTS 对手胜率 | 平局率、先手/后手分胜率 |
| 2048 | 平均得分 | 最大方块值、达到 2048 比例 |

#### 5.3.2 适应效率指标

- **学习收敛曲线**：每个 epoch test 阶段的主指标随 epoch 变化曲线。横轴可切换为累积 learn episode 数以与 RL 方法对齐。报告 5 seeds 的 mean ± 95% CI（移动平均窗口 $w = 3$ epoch）。
- **AUC（Area Under Curve）**：学习曲线归一化到 $[0,1]$ 后的线下面积（trapezoidal rule），衡量样本效率。
- **收敛 epoch**：连续 $E_{\text{conv}} = 3$ epoch test 主指标变化幅度 < 2% 时的首个 epoch。
- **首个达标 epoch**：test 主指标首次达到最终性能 90% 的 epoch。

#### 5.3.3 计算开销指标

| 指标 | 说明 | 统计方式 | 公平性 |
|------|------|---------|--------|
| **Token 开销** | LLM 调用消耗的 prompt + completion tokens | OpenAI/Anthropic API `usage` 字段累加，分初始化编译与进化调用统计 | 机器无关，主指标 |
| **LLM 调用次数** | 分阶段统计 | 初始化编译次数、进化触发次数、每次进化平均 token | 机器无关 |
| **FLOPs 估算** | MCTS 每步估算浮点运算量 | 基于 $N_{\text{sims}} \times D \times \|\bar{\mathcal{A}}\| \times K_{\text{active}}$ 估算（含选择、扩展、回传三阶段），实现方案见 `experiment_plan.md` §3.3 | 机器无关，相对比较 |
| **单步决策时间** | 每次 `select_action()` 耗时 (ms) | `time.perf_counter()` 打点，报告均值和标准差 | 机器相关，仅作参考 |
| **每 epoch wall time** | 单 epoch 学习+验证总耗时 (s) | epoch 起止计时，分 learn/test 阶段报告 | 机器相关，仅作参考 |
| **累计 wall time** | 至收敛/最大 epoch 的总耗时 (h) | 所有 epoch 累加 | 机器相关，仅作参考 |

**说明**：Wall time 受机器性能影响，仅作参考，不作为公平比较的主要依据。Token 开销和 FLOPs 为机器无关指标，用于跨方法资源效率比较。Token 统计的代码实现方案见 `experiment_plan.md` §3.2，FLOPs 估算方案见 `experiment_plan.md` §3.3。

#### 5.3.4 可解释性指标

- **可信度演化追踪**：记录各技能 $\tau_k$ 随 epoch 的演化轨迹。在 Misleading 先验下重点观察误导技能的 $\tau_k$ 能否被压低至 $\theta_{\text{low}} = 0.2$ 以下，正常技能的 $\tau_k$ 能否维持在 ≥1.0。
- **决策案例分析**：选取 3–5 个典型决策时刻，展示状态可视化、激活技能及对应可信度、MoE 先验分布、MCTS 后验分布、最终决策动作。
- **技能可读性**：各技能的代码行数与圈复杂度统计分布。
- **激活覆盖率**：每个 epoch test 阶段中至少有一个技能激活的状态比例，衡量技能库的状态覆盖质量。
- **进化活动追踪**：进化触发次数、修正/新增/淘汰操作数、影子评估通过率。

**公平性控制**：B7（Prompt-MCTS）和 B14（Voyager-Style）获得与 SkillMCTS 同等的 LLM 调用预算。B5 使用交互预算的 $10\%$ 离线预训练小型 CNN，剩余 $90\%$ 在线测试（不更新）。B3 和 B4 使用与 SkillMCTS 完全相同的 epoch 循环配置（$N_{\text{learn}} = 200$，$N_{\text{test}} = 100$），在 learn 阶段进行梯度更新（RL：PPO 在线策略梯度；IL：从 expert policy 收集演示数据后做行为克隆监督学习），在 test 阶段冻结网络参数评估。B4 的 expert policy 为 Uniform-MCTS（$N_{\text{sims}} = 100/1000/200$，与对应环境 SkillMCTS 缺省一致），其交互步数计入交互预算以公平比较。所有方法的 epoch 配置一致（$N_{\text{learn}} = 200$，$N_{\text{test}} = 100$），确保学习曲线的横轴（累积 step）可比。

### 5.5 对比实验

对比实验回答"方法是否有效"，系统对比 SkillMCTS（Ours）与 Group A–C 的 8 项 baseline（B1–B8）。所有对比实验使用缺省 $N_{\text{sims}}$（Sokoban 100，五子棋 1000，2048 200），Standard 先验 + 预处理开启（SkillMCTS 及其消融变体），$N_{\text{seed}} = 5$，完整 epoch 循环。评判指标包括：最终 test 主指标、AUC、收敛 epoch、首个达标 epoch，以及 Token / FLOPs / wall time 等效率指标。

#### 5.5.1 与传统方法对比（Group A：B1–B2）

通过 B1 Random 与 B2 Uniform-MCTS 建立性能下限和无先验 MCTS 参考线。

- **SkillMCTS vs B1**：验证框架是否显著优于随机策略。
- **SkillMCTS vs B2**：量化"技能先验 + 在线适应"相对于纯 MCTS 搜索的总增益，直接体现先验价值。
- **绘图**：每个环境一张学习曲线图，x 轴为累积 learn step（每 episode 按实际步数绘制，横轴非均匀），y 轴为主指标；B1/B2 作为静态水平参考线绘制。

#### 5.5.2 与梯度学习方法对比（Group B：B3–B5）

通过 B3 Deep RL（PPO）、B4 Imitation Learning（BC）、B5 Learned-Prior MCTS，验证无梯度在线适应的相对效率。

- **SkillMCTS vs B3/B4**：在同等交互预算下，比较无梯度技能适应与基于梯度的深度学习方法。重点比较学习曲线、AUC、收敛 epoch、首个达标 epoch、训练稳定性（PPO 奖励方差、BC 分布偏移）。B3/B4 使用与 SkillMCTS 完全相同的 epoch 循环配置（$N_{\text{learn}} = 200$，$N_{\text{test}} = 100$），确保横轴（累积 step）可比。
- **SkillMCTS vs B5**：比较无梯度自适应与小样本离线预训练 CNN policy head 的 MCTS。B5 使用交互预算的 $10\%$ 离线预训练小型 CNN，剩余 $90\%$ 在线测试（不更新）。比较最终性能、预训练开销、样本效率。
- **关键预期**：B3 早期因随机探索冷启动性能低于 SkillMCTS，需要更多 episode 才能收敛；B4 在 Sokoban 等长程规划任务上因 expert 演示质量与分布偏移问题性能显著低于 SkillMCTS；B5 在小样本预训练条件下性能低于 SkillMCTS。B3/B4/B5 共同突显**无梯度自适应**在有限交互场景下的样本效率优势。

#### 5.5.3 与 LLM 决策方法对比（Group C：B6–B8）

通过 B6 LLM-as-Policy、B7 Prompt-MCTS、B8 Memory-LLM+MCTS，验证"编译而非实时调用"及"代码化技能库"的设计价值。

- **SkillMCTS vs B6**：比较 MCTS + 编译后技能库 vs LLM 每步直接输出动作。B6 每步调用 LLM 进行 CoT 推理并解析动作。比较最终性能、单步决策时间、Token 消耗、决策稳定性。
- **SkillMCTS vs B7**：比较编译型先验 vs 每扩展调用 LLM 的实时先验。B7 在每个节点首次扩展时调用 LLM。比较性能、Token 总消耗、每 episode LLM 调用次数、FLOPs。B7 因成本极高，仅在 Standard 先验下运行 2–3 组 $N_{\text{sims}}$ 值（如 Sokoban $\{100, 500\}$）。
- **SkillMCTS vs B8**：B8 为带经验记忆的 LLM+MCTS，具有学习性质，可绘制 AUC 曲线。比较其与 SkillMCTS 的样本效率、记忆机制带来的持续学习效果、LLM 调用频率与决策延迟。
- **LLM 方法综合分析**：从"性能-Token 曲线"和"性能-延迟曲线"两个维度，综合评估 LLM 实时决策、实时先验、记忆增强三种方案与 SkillMCTS 的 trade-off。核心结论是：SkillMCTS 将 LLM 从实时决策者转为离线编译器，在保持性能的同时将运行时 LLM 调用频率从 $O(T \cdot N_{\text{sims}})$ 降至 $O(1/T_{\text{evo}})$。

### 5.6 分析实验

分析实验回答"为什么有效、在什么条件下有效"，按主题分为三类：（i）适应机制分析；（ii）设计消融；（iii）世界模型/其它消融。

#### 5.6.1 适应机制分析（Group D）

##### 5.6.1.1 先验质量 × 预处理联合分析

**实验定位**：本研究最重要的分析实验。直接检验"预处理 + 权重更新 + 进化"这一适应管线在不同质量先验下的鲁棒性与边际贡献，是支撑论文核心声明（"SkillMCTS 能将劣质先验转化为有效策略"）的关键证据。该实验同时生成"先验质量→性能"的基准曲线，作为对比实验 §5.5 中"SkillMCTS vs B2/B9"在不同先验质量下讨论的参照。

**实验范围**：B9、B10、B11、B12 及 SkillMCTS 共 5 种方法 × 四级先验（None/Misleading/Weak/Standard）× 预处理开关（开/关）。B9 与 B10 均关闭权重更新与进化；B9 关闭预处理，B10 开启预处理，二者对照衡量预处理独立贡献；B11 固定预处理关闭；B12 与 SkillMCTS 固定预处理开启。部分组合不适用（如预处理对 None 先验无意义），实际有效组合约 24–30 组，每组 $N_{\text{seed}} = 5$。

**各方法在联合分析中的角色**：

| 方法 | 预处理 | 权重更新 | 进化 | 分析角色 |
|------|--------|---------|------|---------|
| B9（Fixed-Trust） | ✗ | ✗ | ✗ | **基线**：纯技能库，无任何适应 |
| B10（Preprocessed Fixed-Trust） | ✓ | ✗ | ✗ | **预处理独立贡献**：预处理 + 固定信任，无在线适应 |
| B11（no preprocessing） | ✗ | ✓ | ✗ | **权重更新独立贡献**：无预处理，仅在线权重适应 |
| B12（No-Evolution） | ✓ | ✓ | ✗ | **预处理+权重联合贡献**：关闭进化 |
| **SkillMCTS（完整）** | ✓ | ✓ | ✓ | **进化额外贡献**：完整管线 |

**分析维度**：
- 各方法的绝对性能随先验质量的变化趋势（四级先验上的性能排序）；
- 预处理在各先验等级上的绝对增益（$\Delta\text{AUC}$，B10 − B9）；
- 权重更新的边际贡献（B11 − B9，B12 − B10）；
- 进化的边际贡献（SkillMCTS − B12）；
- Misleading 先验下各组件的自校正能力（$\tau_k$ 分化速度、误导技能被压低至 $\theta_{\text{low}}$ 以下的 epoch 数）；
- 预处理的保留/修正/丢弃比例与最终性能的相关性分析。

**关键预期**：预处理增益在 Misleading/Weak 先验下显著，在 Standard 先验下较小；权重更新的贡献在 Misleading 先验下最大（自校正效应）；进化在 2048 和五子棋上的边际贡献大于 Sokoban。

##### 5.6.1.2 $N_{\text{sims}}$ 维度分析

**实验定位**：$N_{\text{sims}}$ 是 MCTS 类方法的关键参数。该分析检验两个核心假设：（1）技能先验在低 $N_{\text{sims}}$ 下提供更大增益（因为先验弥补了模拟不足）；（2）自校正的效率随 $N_{\text{sims}}$ 增加而提升（与命题 3 的理论界对照）。

**实验范围**：
- **全 MCTS 方法**：B2（Uniform-MCTS）、B9、B10、B11、B12、SkillMCTS——各在完整 $N_{\text{sims}}$ 扫描组上运行完整 epoch 循环。
- **高成本方法**：B7（Prompt-MCTS）因 LLM 调用成本限制，仅在 Standard 先验下运行 2–3 组 $N_{\text{sims}}$ 值（如 Sokoban $\{100, 500\}$）。
- **非 MCTS 方法**：B1（Random）、B6（LLM-as-Policy）不涉及 $N_{\text{sims}}$，作为参照。

各环境 $N_{\text{sims}}$ 扫描组见 §5.2.3。

**分析维度**：
- 各方法性能随 $N_{\text{sims}}$ 的 scaling 曲线（性能 vs $N_{\text{sims}}$，log-log 图）；
- **技能先验增益比**：$\text{Gain}(N_{\text{sims}}) = \frac{\text{SolvedRate}_{\text{SkillMCTS}}(N_{\text{sims}})}{\text{SolvedRate}_{\text{B2}}(N_{\text{sims}})}$，检验增益是否在低 $N_{\text{sims}}$ 下更大；
- SkillMCTS 在低 $N_{\text{sims}}$（如 Sokoban $N_{\text{sims}}=50$）时相对于高 $N_{\text{sims}}$ Uniform-MCTS 的性能——检验"技能先验能否替代部分模拟预算"；
- 自校正效率 vs $N_{\text{sims}}$：Misleading 先验下误导技能 $\tau_k$ 降至 $\theta_{\text{low}}$ 以下所需的 learn episode 数随 $N_{\text{sims}}$ 的变化；
- 理论界（命题 3）与实证自校正效率的对比讨论。

##### 5.6.1.3 自校正性质验证

**配置**：B11 条件（无预处理），Misleading 先验。子实验：
- a. **默认初始化**：正常与误导技能均 $\tau_k^{(0)} = 1.0$，观测 $\tau_k$ 分化速度及降至 <0.2 所需 learn episode 数。记录每个 epoch 的 $\tau_k$ 分布。
- b. **对抗性初始化**：误导技能 $\tau_k^{(0)} = 5.0$（$\tau_{\max}$），正常技能 $\tau_k^{(0)} = 1.0$，检验自校正能否克服极端初始偏差。记录 $\tau_k$ 交叉点（正常技能超越误导技能的 epoch）。
- c. **$(c_{\text{puct}}, N_{\text{sims}})$ 联合扫描**：$c_{\text{puct}} \in \{0.5, 1.0, 1.5, 2.0\}$，$N_{\text{sims}} \in \{100, 200, 500, 1000\}$（Sokoban）。特别关注 $N_{\text{sims}}$ 低于理论界时自校正的实际情况，与 §5.6.1.2 的 $N_{\text{sims}}$ 分析交叉引用。

#### 5.6.2 设计消融（Group E + 超参数）

##### 5.6.2.1 乘性权重 vs EMA

B13 vs SkillMCTS。指标：最终性能、$\tau_k$ 轨迹分化程度（标准差与极差）、自校正速度。在 Misleading 和 Standard 两种先验下对比。

##### 5.6.2.2 进化机制消融

三种配置：完整进化 / 无冷却期（$T_{\text{cool}} = 0$）/ 无进化（B12）。参数扫描 $\theta_{\text{low}} \in \{0.1, 0.2, 0.5\}$。指标：最终性能、进化触发次数、影子评估通过率、技能库大小变化曲线。

##### 5.6.2.3 Buffer 批量更新消融

三种写入模式：搜索树节点收集（缺省）vs 仅根节点 vs 逐状态即时更新。双参数扫描：batch size $\in \{5, 10, 20, 50\}$，$\tau_N \in \{0.1, 0.2, 0.3, 0.5\} \cdot N_{\text{sims}}$。指标：$\tau_k$ 轨迹方差、收敛到 $90\%$ 最终值的 learn episode 数、单步 Buffer 操作开销。

##### 5.6.2.4 损失函数消融

三种损失：价值优势（缺省）vs 中心化交叉熵 vs Bhattacharyya 对齐度。指标：$\tau_k$ 收敛速度、自校正成功率、最终性能。特别关注低 $N_{\text{sims}}$ 时 Q/V 估计噪声对不同损失的影响。

##### 5.6.2.5 MoE 组合方式消融

三种组合：归一化加性（缺省）vs 非归一化加性（旧版）vs 乘性 log-linear。在单技能、多技能一致、多技能冲突三种模拟场景下评估。额外对比归一化加性在极端 $\tau_k$ 值（$\tau_{\max}$ 扫描）下的稳定性。

##### 5.6.2.6 探索参数 + 学习率联合消融

网格扫描 $(\lambda, \eta)$：$\lambda \in \{0.01, 0.02, 0.05, 0.1\}$，$\eta \in \{0.01, 0.02, 0.05, 0.1\}$。加上 $\tau_{\max} \in \{2.0, 5.0, 10.0, \infty\}$ 的扫描。

#### 5.6.3 世界模型 / 其它消融

对比开源环境（缺省）vs LLM 生成 $\mathcal{M}_0$。指标：性能差异、Sokoban 死局检测缺失的影响。

### 5.7 实验流程与统计

**通用流程**：所有对比实验和分析实验运行 $N_{\text{seed}} = 5$ 个独立随机种子（不同种子对应不同的环境随机性、关卡采样顺序和对手落子顺序）。初始化阶段 $3$ 次独立 LLM 调用（对同一组先验文本重复编译），取中位数性能的编译结果用于后续所有 epoch，以控制 LLM 随机性的影响。

**统计检验**：最终 epoch 的 test 主指标在 5 seeds 上进行配对 Wilcoxon 符号秩检验（$p < 0.05$）。多组比较（如 §5.6.1.1 的方法 × 先验矩阵）使用 Benjamini-Hochberg FDR 控制。报告效应量（Cliff's $\delta$）。

**学习曲线**：每个 epoch 计算 test 指标在 5 seeds 上的 mean ± std。移动平均窗口 $w = 3$ epoch（以匹配 $E_{\text{conv}} = 3$ 的收敛判定尺度），报告 95% CI（$1.96 \times \text{std} / \sqrt{N_{\text{seed}}}$）。

**Epoch 循环的统计独立性**：每个 seed 内的 learn 和 test 阶段共享技能库状态（test 从 learn 的 checkpoint 加载后冻结），因此单个 seed 的 epoch 序列构成一条独立的适应轨迹。跨 seed 的均值和方差反映初始化和环境随机性的综合影响。

### 5.8 预期结果

- **对比实验**：SkillMCTS（Standard + 预处理）在三个环境均显著优于 Group A–C 的 baseline（B1–B8）。学习曲线呈现典型的上升-收敛形态，收敛前 3–8 epoch 的适应效率最高。
  - **Group A**：SkillMCTS 显著优于 B1 Random 与 B2 Uniform-MCTS，体现技能先验 + 在线适应的总增益。
  - **Group B**：SkillMCTS 在样本效率和最终性能上优于 B3 Deep RL、B4 Imitation Learning 与 B5 Learned-Prior MCTS。B3 早期因随机探索冷启动性能较低，需要更多 episode 收敛；B4 在 Sokoban 等长程规划任务上因 expert 演示质量与分布偏移问题性能较低；B5 在小样本预训练条件下性能低于 SkillMCTS。B3/B4/B5 共同突显**无梯度自适应**在有限交互场景下的样本效率优势。
  - **Group C**：SkillMCTS 在性能-Token 和性能-延迟两个维度上优于 B6 LLM-as-Policy、B7 Prompt-MCTS 与 B8 Memory-LLM+MCTS。B6/B7 因每步或每扩展调用 LLM 导致 Token 消耗和决策延迟极高；B8 虽具备持续学习能力，但 LLM 调用频率仍高于 SkillMCTS。
- **先验质量 × 方法**（§5.6.1.1）：B11 vs SkillMCTS 的差距在 Misleading 先验下最大，在 Weak 下次之，在 Standard 下最小。预处理（B10 − B9）在 Misleading/Weak 先验下提供显著增益，在 Standard 下增益较小。权重更新（B11 − B9，B12 − B10）在 Misleading 先验下贡献最大。进化（B12 vs SkillMCTS）在 2048 和五子棋上贡献显著，在 Sokoban 上贡献较小。
- **$N_{\text{sims}}$ 分析**（§5.6.1.2）：SkillMCTS 在低 $N_{\text{sims}}$ 下相对于 Uniform-MCTS 的性能增益最大（技能先验弥补模拟不足）；随 $N_{\text{sims}}$ 增大，增益递减但保持正值。Misleading 先验下的自校正效率随 $N_{\text{sims}}$ 增大而显著提升。
- **MW vs EMA**（§5.6.2.1）：B13（EMA-SkillMCTS）与 SkillMCTS 各有优势——EMA 在 Standard 先验下更稳定（$\tau_k$ 方差更小），乘性权重在 Misleading 先验下自校正更快（$\tau_k$ 分化更早）。
- **进化价值**（§5.6.2.2）：B12（No-Evolution）vs SkillMCTS 的差异在 2048 上最明显（环境随机性强，技能库需要持续扩展），在 Sokoban 上较小（技能逻辑相对稳定）。
- **设计选择验证**：价值优势损失在自校正速度上优于交叉熵损失，但在极低 $N_{\text{sims}}$ 时受 Q/V 估计噪声影响可能不如交叉熵稳定。归一化加性组合在 $\tau_k$ 极端值时比非归一化版本更稳定。

### 5.9 失败案例分析

- **案例 1（确认偏误残留）**：$N_{\text{sims}}$ 不足（如 Sokoban $N_{\text{sims}} = 50$）时误导技能 $\tau_k$ 下降缓慢。选取具体 episode 展示搜索树后验仍被误导先验主导的证据。
- **案例 2（进化失败）**：影子评估拒绝技能替换的案例——新技能在 Buffer 上的平均损失未严格低于旧技能。分析失败原因（修改过度、诊断错误、或旧技能在特定状态下仍有价值）。
- **案例 3（技能冲突仲裁）**：多高可信度技能推荐矛盾时，MCTS 搜索如何通过 PUCT 探索自然仲裁，以及后续 $\tau_k$ 的级联调整过程。
- **案例 4（盲区填补质量）**：LLM 新增技能对覆盖盲区的覆盖率与策略质量。评估新技能是否真正填补了盲区，还是仅提供了退化的默认策略。
- **案例 5（预处理误判）**：LLM 预评估假阳性（误保留误导条目）与假阴性（误丢弃有效条目）的频率及其对最终性能的影响。
- **案例 6（$\tau_k$ 触及上界）**：$\tau_{\max} = 5.0$ 激活的频率与对技能相对权重的影响。检验在 Standard 先验 + 长期运行下是否出现多技能同时触及 $\tau_{\max}$ 导致区分度丧失。

## 6. 结论

本文提出了 SkillMCTS 框架，针对"在无预训练数据、无梯度更新的结构化 MDP 中实现快速自适应决策"这一核心挑战，给出了一个从语言先验到自进化技能的完整解方案。

SkillMCTS 的核心思想是：**将 LLM 从实时决策者重新定位为策略假设的编译器与进化引导者**，以代码化技能库作为语言与决策之间的桥梁。技能不仅是可执行的决策模块，更是可验证的策略假设——MCTS 搜索树高访问节点的后验分布为每项技能提供了零外部监督的"质量检验报告"。本框架的特色在于：MoE 组合通过激活集内归一化确保探索的一致性；乘性权重更新以价值优势为损失、通过"优者留存且增强、劣者衰减至静音"的指数机制实现技能筛选；$\tau_{\max}$ 上界防止可信度过度集中。

在方法论层面，本文的三项核心贡献相互支撑：（1）**代码化技能编译与后验验证闭环**——将语言先验编译为模块化专家技能，以 MoE 协同决策，利用搜索树后验 + 乘性权重批量更新形成闭环；（2）**乘性权重自进化学习与适应机制**——以乘性权重可信度更新（快时间尺度）和可信度驱动的技能进化（慢时间尺度）共同构成无梯度自进化能力，具有 $O(\sqrt{T \log K})$ 遗憾界；（3）**多环境实验验证**——在 Sokoban、五子棋和 2048 三个互补环境中通过四级先验质量分层、16 项系统性 baseline 和若干核心分析实验（含适应机制分析、设计消融、世界模型消融），全面验证了框架各组件的有效性，并与深度 RL、模仿学习等方法在样本效率上展开了公平对比。

**局限性**：（1）乘性权重对损失估计噪声敏感（exp 放大误差），在极小 batch size 或极低 $N_{\text{sims}}$ 时 $\tau_k$ 轨迹可能不稳定；（2）价值优势损失依赖 Q/V 估计质量，高维动作空间中有限模拟次数下的估计噪声可能影响自校正效率；（3）世界模型的 LLM 生成可靠性受环境复杂度影响；（4）技能进化环节对 LLM 代码生成质量的依赖引入了外部不确定性。

**未来方向**：（1）将框架扩展至部分可观测环境（POMDP）与多智能体协作/博弈场景；（2）研究技能库的跨任务结构化迁移——从一项任务中学到的技能资产如何最小化修改地迁移至同类但不同尺度的新任务；（3）探索乘性权重与加性更新（EMA）的混合策略——在不同阶段或不同技能类别使用不同的更新机制，取两者之长。

## 附录

### A. 理论分析

#### A.1 带裁剪的乘性权重更新遗憾界

**命题 1（带 τ_max 裁剪的乘性权重 = Hedge）**。考虑技能 $k$ 的 $T$ 次 batch 更新序列。在有限奖励 MDP 中价值优势有界，损失跨度 $L_{\text{range}} = 2(R_{\max}-R_{\min})$。乘性更新 $\tau_k^{(t+1)} = \operatorname{clip}_{[\tau_{\min}, \tau_{\max}]}(\tau_k^{(t)} \cdot \exp(-\eta \bar{\ell}_k^{(t)}))$。定义归一化权重 $w_k^{(t)} = \tau_k^{(t)} / \sum_{j=1}^{K} \tau_j^{(t)}$。则对任意固定专家 $k^*$：

$$\sum_{t=1}^{T} \sum_{k=1}^{K} w_k^{(t)} \bar{\ell}_k^{(t)} - \sum_{t=1}^{T} \bar{\ell}_{k^*}^{(t)} \le \frac{\log K + K \cdot \log(\tau_{\max}/\tau_{\min})}{\eta} + \frac{\eta T L_{\text{range}}^2}{8}$$

*证明概要*。定义 $W_t = \sum_k \tau_k^{(t)}$。与标准 Hedge 证明相同，但 $\tau_{\max}$ 裁剪引入了 $W_t$ 的额外上界：对任意 $t$，$K \tau_{\min} \le W_t \le K \tau_{\max}$。因此 $\log(W_T/W_1) \le \log(K \tau_{\max} / K \tau_{\min}) = \log(\tau_{\max}/\tau_{\min})$。代入 Hoeffding 引理并求和，与标准证明完全一致，仅初始对数项中多出 $K \cdot \log(\tau_{\max}/\tau_{\min})$ 的常数项。取 $\eta = \sqrt{8(\log K + K\log(\tau_{\max}/\tau_{\min})) / (T L_{\text{range}}^2)}$，遗憾为 $O(\sqrt{T \log K})$。$\square$

$\tau_{\max}$ 裁剪仅引入 $O(1)$ 的附加常数项，不影响渐近遗憾界。在非归一化形式下，$\tau_k$ 的独立演化 + 组合阶段的激活集内归一化使先验混合的稳定性独立于 $\tau_k$ 的绝对量级。

#### A.2 自校正的有限样本分析

**命题 2（渐近无偏性，Rosin 2011）**。设 MCTS 使用 PUCT 公式 (4)，$c_{\text{puct}} > 0$。当 $N_{\text{sims}} \to \infty$ 时，根节点后验 $\hat{\pi}(a|s)$ 收敛到真实最优动作分布，与先验 $\pi_{\mathcal{H}}$ 无关。

**命题 3（有限样本自校正条件）**。设状态 $s$ 下，技能 $k$ 的核心推荐动作 $a_k$ 为次优，存在更优动作 $a^*$ 满足 $Q(s,a^*) - Q(s,a_k) = \Delta > 0$。设合法动作数为 $|\mathcal{A}|$，PUCT 常数为 $c_{\text{puct}}$。则当

$$N_{\text{sims}} > \frac{4c_{\text{puct}}^2 \cdot |\mathcal{A}|}{\lambda \cdot \Delta^2} \cdot \log\frac{2}{\delta}$$

时，以概率至少 $1-\delta$，后验偏好 $a^*$ 超过 $a_k$，触发 $\tau_k$ 自校正。

*证明概要*。$\lambda$ 确保 $a^*$ 每次模拟第一步以概率 $\ge \lambda/|\mathcal{A}|$ 被选中，$N_{\text{sims}}$ 次模拟中期望访问次数 $\ge \lambda N_{\text{sims}}/|\mathcal{A}|$。由 Hoeffding 不等式，$n$ 次访问后 $\hat{Q}(s,a^*)$ 的估计误差以 $1-\delta$ 概率 $\le \sqrt{\log(2/\delta)/(2n)}$。PUCT 先验项系数随访问量衰减，当 $N(s,a_k)$ 充分大时先验偏差影响可忽略。此时若两个 $Q$ 值估计误差均 $< \Delta/2$，$a^*$ 的 UCB 超越 $a_k$。$\square$

**说明**：该 bound 基于最坏情况假设（技能将全部概率集中在次优动作上），是充分非必要条件。实际自校正因多技能探索、MCTS roll-out 的贡献及 $\tau_{\max}$ 上限约束而显著快于此界。实验中通过自校正分析实验（§5.6.1.3）实证验证有限 $N_{\text{sims}}$ 下的自校正效率。

#### A.3 组合阶段归一化的动机

在 $A(s)$ 内对 $\tau_k$ 归一化（式 1）在单技能激活的退化情况下自动退化为 $w_k=1$，保持技能原始策略的完整表达。在多技能激活时，归一化使 $\lambda$ 的有效探索率在所有状态下保持一致，避免高 $\tau_k$ 或大量激活技能导致的探索稀释。同时，$\tau_k$ 的非归一化演化保留了对进化触发的绝对判断能力。这一"分阶段归一化"实现了可信度的积累（更新）与使用（组合）的解耦。

### B. 实现细节

**B.1 MoE 先验组合（单函数技能，归一化版本）**

```python
def additive_moe_prior(state, legal_actions, skills, tau, lam, delta=0.1):
    """归一化加性 MoE 先验组合（v1.4 单函数接口）。
    
    1. 调用各技能 f_k(state, actions) 得 (m_k, π_k)
    2. 激活集内归一化: w_k = (m_k·τ_k) / Σ_j (m_j·τ_j)
    3. π_H = (1-λ)·Σ w_k·π_k + λ/|A_legal|
    """
    n_legal = len(legal_actions)
    active = []
    for k, skill in enumerate(skills):
        m_k, pi_k = skill.fn(state, legal_actions)
        if m_k > delta:
            active.append((m_k, pi_k, tau[k]))
    
    if not active:
        return np.ones(n_legal) / n_legal
    
    # 激活集内归一化
    total_weight = sum(m * t for m, _, t in active)
    weights = [m * t / total_weight for m, _, t in active]
    
    score = np.zeros(n_legal)
    for w, (_, pi_k, _) in zip(weights, active):
        score += w * pi_k
    
    # λ 混合 + 归一化
    pi_h = (1.0 - lam) * score + lam / n_legal
    return pi_h / pi_h.sum()
```

**B.2 价值优势损失与乘性权重更新**

```python
def value_advantage_loss(pi_k, Q_hat, V_hat):
    """ℓ_k = V̂ - Σ_a π_k(a)·Q̂(s,a)"""
    return V_hat - np.sum(pi_k * Q_hat)

def batch_mw_trust_update(skills, buffer, eta=0.05, 
                          tau_min=1e-3, tau_max=5.0):
    """乘性权重批量可信度更新（含τ_max裁剪）。"""
    if len(buffer) == 0:
        return
    batch = random.sample(buffer, min(20, len(buffer)))
    for k, skill in enumerate(skills):
        losses = []
        for entry in batch:
            # 单函数调用：直接得到匹配度和推荐分布
            m_k, pi_k = skill.fn(entry["state"], entry["actions"])
            if m_k > skill.threshold:
                loss = value_advantage_loss(pi_k, entry["q_values"], entry["v_hat"])
                losses.append(m_k * loss)  # 适用度加权
        if losses:
            mean_loss = np.mean(losses)
            skill.tau = np.clip(
                skill.tau * np.exp(-eta * mean_loss), 
                tau_min, tau_max
            )
```

### C. 技能组件接口规范

v1.4 采用函数式技能接口：每个技能以单一函数表示，将状态解析与策略推荐合并为一步。

```python
from typing import Tuple, List
import numpy as np

def skill_<name>(state: np.ndarray, legal_actions: List[int]) -> Tuple[float, np.ndarray]:
    """技能函数：状态解析与策略推荐合并为单一函数。
    
    Args:
        state: 环境状态。
        legal_actions: 合法动作列表。
    
    Returns:
        match_score: 适用度 ∈ [0, 1]。
        action_probs: 动作推荐概率分布，长度 = len(legal_actions)。
    """
    # ... 状态解析 + 动作打分逻辑 ...
    match_score = 0.0
    scores = np.zeros(len(legal_actions))
    # ... 为每个动作计算得分 ...
    total = scores.sum()
    if total > 0:
        probs = scores / total
    else:
        probs = np.ones(len(legal_actions)) / len(legal_actions)
    return match_score, probs
```

```python
def skill_block_open_three(state, legal_actions):
    """When: opponent has open-three | Strategy: block the extension direction"""
    threats = detect_open_three(state, player=-1)
    match_score = 1.0 if threats else 0.0
    
    scores = np.zeros(len(legal_actions))
    for i, a in enumerate(legal_actions):
        for t in threats:
            if a == t["block_pos"]:
                scores[i] += 1.0
    
    total = scores.sum()
    if total > 0:
        probs = scores / total
    else:
        probs = np.ones(len(legal_actions)) / len(legal_actions)
    return match_score, probs
```

### D. 扩展讨论

**D.1 价值优势 vs 交叉熵损失**：价值优势直接利用 MCTS 的 Q/V 估计，信号与决策质量直接挂钩——技能的价值优势越高，其对累积奖励的贡献越大，与最终优化目标天然对齐。交叉熵损失利用 MCTS 后验的完整分布信息，但度量的是分布匹配而非决策质量。两种损失的实证对比见分析实验 §5.6.2.4。

**D.2 $\tau_{\max}$ 上界的实践考量**：$\tau_{\max} = 5.0$ 的选择基于以下考量：初始 $\tau_k \in [0.5, 1.5]$（预评估差异化），$\tau_{\max} = 5.0$ 允许最优技能的可信度增长约 3–10 倍，在提供充分区分度的同时防止单一技能垄断先验。在分析实验 §5.6.2.6 中扫描 $\tau_{\max} \in \{2.0, 5.0, 10.0, \infty\}$ 以实证验证这一选择。

**D.3 组合阶段归一化的退化行为**：单技能激活时，$w_k = 1$（归一化权重退化为恒等映射），技能以其原始策略 $\pi_k$ 的强度贡献先验。多技能激活时，$w_k$ 反映技能间的相对可信度与适用度。$\tau_k \to 0$ 的技能在组合中的贡献被衰减至可忽略（被"静音"），$\tau_k \to \tau_{\max}$ 的技能获得最大话语权但不会垄断（归一化保证其他技能至少通过 $\lambda$ 混合保留一定的探索概率）。

**D.4 POMDP 扩展**：对于部分可观测环境，将 $f_k(s, \mathcal{A}_{\text{legal}})$ 扩展为 $f_k(o_{1:t}, \mathcal{A}_{\text{legal}})$（基于观测历史），采用粒子滤波维护信念状态，其他组件保持不变。

**D.5 博弈环境**：五子棋中 MCTS 对手节点采用 Negamax。乘性权重更新从当前 Agent 视角出发——$\hat{\pi}$ 为当前对手策略下的根节点后验，价值优势损失追踪的始终是"在当前对手面前该技能的有效性"。
